### 9.2 需要注意的设计要点

1. **同池加算的"坑"与"机会"**
   - `DamagePhysical(23)` 与 `DamagePercent(65)` 同池 → 同时堆会稀释。
   - 条件伤害 10 项同池 → 堆多项边际递减，但对不同敌人场景可全覆盖。
2. **独立乘区的稀缺性**
   - 真正独立乘算的只有：暴击、易伤 `×1.3`、命中浮动、以及**减伤层**（防御侧三项互乘）。
   - 因此 Build 优化的正解是"解锁新乘区"，而非堆高已有乘区百分比。
3. **暴击的双重封顶**
   - `System.Enum` 层面 `bjl()` 已 clamp 0.85，`bkk()` 再 clamp 一次 → 实际硬上限 **85%**。
4. **易伤是"标记 + 数值"双重机制**
   - 状态本身给 `×1.3`（固定，不可堆）；
   - 攻击方的 `VulnerableDamage(40)` 只在目标带标记时计入条件池，因此**必须先保证挂标覆盖率**。
5. **`HeroClass` 与 `WorldDifficultyMask` 是位标志**
   - `HeroClass.All = 15`，`WorldDifficultyMask.All = -1`（全位）；`ItemData.UsableClasses` 用位与判断。
6. **`AbilityTag.None = 9999`**
   - 是一个非常规的哨兵值，遍历标签数组时需注意。
7. **`EncounterData` 内含预生成数值**
   - `EnemySpawnEntry` 的 `PlannedXP` / `PlannedBaseHealth` / `PlannedBaseDamage` 是**设计期预计算**结果，说明关卡数值在编辑器内一次性烘焙，运行时仅按等级区间成长曲线缩放。
8. **反作弊数值存储**
   - 所有 `ObscuredFloat`/`ObscuredInt`/`ObscuredLong` 字段以 `hiddenValue XOR key` 存储，直接改存档无效。
9. **`ItemRarity` 有 6 档，但 `LootVector` 只有 5 档**
   - `Divine` 与 `RuneSet` 通过独立的 `DivineChance` 分支处理，不参与主掉落向量。
10. **`MythicEnemySize` 从 1 开始**
    - `Small=1`（非 0），注意索引转换。

## 11. 补充结论：SerializeReference 载荷 · 词条 Roll · 传奇特效 ✅

> 本节闭环第 08 篇遗留待办，结论均有指令级证据或字节级解码支撑。

### 11.1 `[SerializeReference]` 托管引用段布局 ✅

`AbilityData.Effects` / `StatusEffectData.Behaviors` 等 SR 字段的**主数据流只存** `int32 count` + 每元素 8 字节
managed-ref 键（"指针"）；真正的对象载荷追加在**对象字段区之后**：

```
[对象正常字段…]
[int32 A][int32 N]                                   ← 托管引用段头
N × { [u64 typeHash][string 类型名][string 命名空间][string 汇编名][该类型序列化字段…] }
```

**类型名以明文存储**，故具体类型 100% 可判定（无需靠长度猜测）。

- 技能效果 `AbilityData.Effects`：**124 / 124** 全部解出
- 状态行为 `StatusEffectData.Behaviors`：**95 / 95** 全部解出 —— `Behaviors` 为空的记录同样写出
  `[A=2][N=0]` 托管段头（此前被解码器跳过，残留 8 字节）；且对象尾部有 ≤3 字节 4 对齐零填充。
  修正 `decode_object_ex`（无论 SR 计数是否为 0 都尝试托管段 + 校验尾部只剩零填充）后，
  **全库 1333 条 SO 全部字节精确、0 残留**。

### 11.2 技能伤害倍率 ✅

`DamageEffect` 字段（已解出）：`BaseDamage:long`、`AttackScaling:LeveledFloat`、`CanCrit`、`IsDirect`、
`DamageType`、`MoveStutter`、`AttackScalingToken`、`BaseDamageToken`。

```
技能倍率(level) = AttackScaling.Base + max(0, level − 1) × AttackScaling.PerLevel
```

样例：`FireElementalMeteor` → `Base 4.2196 + 0.06115 × (lv−1)`，`DamageType = Fire`，`CanCrit = true`；
且为**链式结构**：`SpawnParticleAoEEffect(Lifetime 3.0s, RehitInterval 0.3s)` → 内嵌 `DamageEffect` + `ApplyStatusEffectEffect`。
（合成链路已逐指令复核 ✅：`te(h)`(0x497FE0) 实为**描述/Token 收集**（对 `AttackScalingToken`/`BaseDamageToken`
调用 `h.tk(TokenSpec, LeveledFloat)`）；伤害执行入口是 `tc(c)`(0x4980F0)：`level = c.se()` →
`scaling = AttackScaling.wo(level)` → `attackDamage = 攻击者.bjr(BaseDamage, scaling)` → `× bkn(元素)`（最后截断一次）。
`Character.bjr`(0x680400) = `trunc(BaseDamage + scaling × Final(Damage=3))`；
`Player.bjr`(0x509D80) = `trunc((BaseDamage + scaling × (trunc(Final(WeaponDamage=20)) + Final(Damage=3))) × (1 + Final(主属性)/100))`，
主属性由 `Player.fak()` 按武器返回 STR/DEX/INT 之一，常量分母 `100.0`@0x18362A370。）

### 11.3 装备词条 Roll 公式 ✅

来源：`gg.dna`(RVA `0x76F5F0`)、`gg.dnt`(RVA `0x771590`)、`gg..cctor`(RVA `0x771DC0`，`Dictionary<StatType,float>`)。

```
perLevel[stat] = 系数表（55 项）
base           = itemLevel × perLevel[stat]      (+5 当 stat == WeaponDamage(20))
rollFactor     = 1.15（取最大） 或 Random(0.85, 1.15)（正常掉落）
rarityMul      = { Common:+0.2, Uncommon:+0.4, Rare:+0.5, Legendary:+0.6, 其他:+0 }
value          = (1 + rarityMul) × base × rollFactor     → 保留 3 位小数；下限 0.001
```

校验（Lv70 Legendary）：暴击率 `[0.008, 0.010]`、暴击伤害 `[0.057, 0.077]`、全伤害% `[0.038, 0.052]`。

### 11.4 传奇 / 天赋 / 生活技能特效 ✅

`EquipmentEffectBehavior` / `TalentEffectBehavior` / `LifeSkillNodeEffect` 均**继承 ScriptableObject**，
是以 PPtr 引用的**独立资产**（非 SR 载荷），按对象头 `m_Script` 反查 MonoScript 得类名后，用同一 schema 即可解码：

| 资产类 | 数量 | 样例 |
|---|---:|---|
| `EquipmentEffect_*` | 92 | `DivineHelm2` 全局减伤 +0.397；`LegendaryChestArmor6` 闪避→物理减伤 ×0.5；`DivineHelm1(AllStats)` 三主属性各 +0.3；`LegendaryChestArmor2` 最大生命% **−0.176**（负面） |
| `TalentEffect_*` | 157 | `StatConversion` / `ConditionalCritChance` / `ConditionalBonusDamage` … |
| `LifeSkillEffect_*` | 36 | `StatModifier` / `OfflineTimeCap` / `MaterialCarryCap` … |

> 唯一未自动代入者为 `EquipmentEffect_StatConversion`（`TargetStat += SourceStat × Fraction`），需运行时源属性实值。

### 11.5 条件暴击接口 `bkl` / `bgm` ✅

- **默认桩**：`StatusEffectBehavior` Slot 12–16（`xo/xq/xr/xm/yi`）与 `Character.bkl` 共址于 `0x4B0C20`–`0x4B0C40`，均为返回 0 的空实现。
- **`Player.bkl(Character target, AbilityData ability)`**（0x505860，覆写 Slot 14）：
  `fgw(ability)`（技能级加成）+ `Σ nub[(TargetStateCondition, bonus)]` 条件命中即加 +
  `Σ nud[(Condition, StatusEffectData, bonus, AbilityData, AbilityTag)]` 经 `fgl()` 状态判定与 `bb.wf()` 技能匹配后加。
  - 条件集合 = `TargetStateCondition`：`Vulnerable(0)`→读 `SEC[+0x60]`、`Stunned(1)`→`bkd()`、`Slowed(2)`→`bkb()`、
    `Elite(3)`→虚接口、`Immobilized(4)`→`bke()`、`SpecificStatus(5)`→恒 false、`Distant(6)`→`bkj(self,target)`（跳转表 0x180505EA4）。
- **`StatusEffectController.bgm(Character target)`**（0x4D65B0）= 遍历生效状态实例（`SEC+0x20` 列表 → 实例+0x10 → 行为列表+0x60），
  累加每个行为的 Slot 16 `yi(bk, Character)` 返回值。实例：`SourceCritChanceBonusBehavior.BonusCritChance`（0x4B0550）。
- **家族虚接口语义**（默认全为 0 桩）：Slot13 `xq` 增伤（`DamageAmplificationBehavior`）、Slot14 `xr` 减伤
  （`DamageDealtReductionBehavior`）、Slot15 `xm` 控制递减（`CCDiminishBehavior`）、Slot16 `yi` 暴击加成。
- 完整暴击率：`critChance = clamp( bjl() + SEC.bgm(target) + bkl(target, ability), 0, 0.85 )`。

**解码器实现要点**（供后续复用）：

1. assets 无内嵌 TypeTree → 从 `dump.cs` 的字段声明顺序重建 schema
2. **对齐规则**：所有字段 4 字节对齐，`long`/`double` **也按 4 对齐**（`ALIGN8 = false`）；`bool`/`byte`/`short` 占 4 字节
3. **`[HideInInspector]` 字段仍会序列化**（`Character._level` 即靠此对齐）
4. **`static`/`const`/`readonly` 不序列化**
5. `ObscuredFloat = 28B`、`ObscuredInt = 12B`、`ObscuredLong = 20B`（序列化尺寸 ≠ IL2CPP 内存尺寸）；明文 = `hiddenValue XOR currentCryptoKey`
6. 构建期实测：`EnemySpawnEntry` 的 `PlannedXP` / `PlannedBaseHealth` / `PlannedBaseDamage` / `PlannedIsBoss` 与 `EncounterData.BossPrefab` **实际未序列化**（仅按此假设 76/76 个 `MapData` 才字节精确）
7. **`[SerializeReference]` 载荷**：主数据流仅存 `count + 8B 键`；实际对象在**字段区之后**的托管引用段
   `[int32 A][int32 N]` + `N × ([u64 hash][string 类型名][string 命名空间][string 汇编名][字段…])`，类型名为明文
8. **SO 效果资产**：`EquipmentEffect_*` / `TalentEffect_*` / `LifeSkillNodeEffect` 为独立 ScriptableObject，
   经对象头 `m_Script`（偏移 `0x10` 起 12B PPtr）反查 MonoScript 得类名后再用对应 schema 解码
