## 核心结论速览

**数值骨架（详见 04）**

```
Final(stat) = (Base + ΣFlat) × (1 + ΣPercentAdd) × Π(1 + PercentMult)

伤害 = 攻强 × [1 + 元素伤害 + 全伤害加成]   ← 同池加算（乘区 A）
           × (1 + 暴伤)                    ← 仅暴击，独立乘算（乘区 B）
           × (1 + Σ 10 项条件伤害)          ← 同池加算（乘区 C）
           × 1.3                           ← 目标易伤，固定乘区（乘区 D）
           × Random(0.9, 1.1)              ← 命中浮动
           × (1 − 护甲曲线) × (1 − 元素减伤) × (1 − 全局减伤)   ← 减伤层，乘法叠加
```

**三条最值得注意的设计结论**

1. **元素/物理伤害% 与"全伤害加成"是同一加算池** —— 面板 312.4% + 88.3% 实为 `×5.007`，而非 `×4.124 × 1.883`。
2. **真正稀缺的独立乘区只有 4 个**（暴击、条件伤害池、易伤 1.3、命中浮动），优化方向是"解锁新乘区"而非堆高已有乘区百分比。
3. **输出位稀缺性收敛在 Weapon / Ring / Necklace** —— 三件同时垄断乘区 A 的两个加算项、乘区 C 的核心项，且武器独占最多宝石孔（3 个）。

**本轮新增闭环（详见 08 篇 §11）**：`[SerializeReference]` 托管引用段布局、技能伤害倍率（`DamageEffect.AttackScaling`）、
装备词条 Roll 公式（55 项系数表）、传奇/天赋/生活技能特效（285 个 SO 资产）、DDS2 存档加解密；
以及 2026-10-07 四项收尾：`ItemizationConfig` 三表逐项值（SHA-256 自校验）、伤害合成链路（`tc`→`bjr` 单次截断）、
条件暴击接口 `bkl`/`bgm`、托管段 95/95（全库 1333 条 0 残留）。

**注意：游戏存在两套 `GameConfig`**（同名类，按资产文件区分），`MaxPlayerLevel` 分别为 **35**（Beta，`resources.assets`）与 **70**（正式，`sharedassets0.assets`）。详见 06 篇。
