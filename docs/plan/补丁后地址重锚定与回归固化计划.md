# 补丁后地址重锚定与回归固化 · 工程实施计划

> 起因为 2026-10-10 08:21 的 Steam 补丁。本文覆盖四项遗留工作：**① RVA 体检与自动重算 · ② 语义别名表 · ③ 文档置信度升级 · ④ 补丁回归流程固化**。
> 进度记录：`docs/plan/PROGRESS-补丁回归.md`；阻塞记录：`docs/plan/BLOCKED-补丁回归.md`。

## 1. Summary

补丁一改，仓库里所有写死的地址就集体失效，而这次只修了一条链（内存导入链），其余 14 个文件里的地址**没人核过**。
本计划的目标：把「补丁后重锚定」从一次性的手工活，变成能重复跑、能自检、失败会吭声的流程——下次补丁花 5 分钟，而不是一整天。

四项工作各自的完成标准：① 一条命令列出并重算全仓地址；② 文档与脚本不再直接引用每版都变的混淆名；③ 文档里的「推断」要么升成实证、要么写明暂缓理由；④ 补丁回归五步写成清单并被一次演练验证。

### 3.1 任务① RVA 体检与自动重算（建议先做）

**必须先做的一步：分类**。命中项未必都是 RVA——可能是颜色、位掩码、尺寸常量。第一步要把每个命中归入：
(a) 真·代码/数据地址（需重算）· (b) 结构偏移（补丁不改，仅需确认）· (c) 无关常量（加白名单并写明理由）。

**步骤**
1. 写 `tools/scripts/rva_audit.py`：扫描 → 分类 → 与 `data/schema/dump.cs` 比对（地址落在哪个方法/是否仍是那个签名）→ 输出 `docs/reports/RVA体检报告.md` + 机器可读 `data/schema/rva_audit.json`（原写 `docs/plan/`，2026-10-10 文档结构优化后机器产物统一放 `docs/reports/`）。
2. 重算仅做**报告**，不自动写回源码；写回留给人工复核后单独提交（见「拍板」第 2 条）。
3. 对无法用签名判定的条目，用 REA 反编译抽查（`procedure_pseudo_code` / `read_bytes`），把证据地址记进报告。

**验收命令**
```powershell

python rva_audit.py --check            # 存在「已失效」条目时退出码非 0

cd tools; ..\.venv-gui\Scripts\python.exe -m deskrawl_gui --selftest # 14/14
```

**防作弊条款（违反即不合格）**
- 不许为了让 `--check` 变绿而把失效项从扫描范围里排除；白名单每条必须写明「为什么不是地址」。
- 不许删除源码里的地址注释来「消除」命中；命中数只许降（真失效被修）或平（加了合理白名单）。
- 自检脚本必须能被证伪：故意把一个已知有效地址改错，`--check` 必须报红（把这次输出贴进报告）。

**止损**：某文件的命中项若无法分类（既不像地址也不像常量），标「人工确认」并列出，不猜。

### 3.2 任务② 语义别名表

**目标**：文档与脚本不再引用每版都变的混淆名（`bjr`/`bkn`/`nsq`…），改引用稳定的**语义名**，由一张表映射到「当期名 + 当期地址」。

**产出**
- `data/schema/aliases.json`：`{ 语义名: { 说明, 历史: [ {构建, 名, 地址} ], 签名, 最后确认 } }`，首批条目取 `docs/08 §12.3` 的映射表（`bjr`→`bkn`、`bkn`→`bll`、`bko`→`blm`、`bkq`→`blo`、`bku`→`bls`、`bkt`→`blr`、`bgm`→`bhg`、`fgl`→`fji`）。
- `tools/scripts/build_aliases.py`：读新旧两份 `dump.cs`，按**签名 + Slot** 匹配生成/校验别名；`--check` 校验当期地址与 dump 一致。

**验收命令**
```powershell
cd d:\workspace\Deskrawl-Reverse\tools\scripts
python build_aliases.py --check   # 退出码 0：每个语义名的当期地址都能在当期 dump.cs 中按签名找到
```

**防作弊条款**：`--check` 必须真正读 `dump.cs` 比对签名，不许只比对文档里抄下来的字符串；别名条目数只增不减（除非写明删除理由）。

### 3.3 任务③ 文档置信度升级（🔶 → ✅）

**目标**：把文档里标「🔶 高置信推断」的条目逐条核成「✅ 指令级证据」，或写明暂缓理由。

**步骤**
1. 扫描 `docs/*.md` 的 🔶 条目，生成待核清单（编号 + 出处 + 待核命题）。
2. 每条用 REA 反编译取证据（函数名 + 地址 + 关键表达式），写进文档原地替换标注。
3. 无法核证的（如依赖 SO 数据而非代码）标注「暂缓 + 理由 + 复核所需条件」，不许直接改成 ✅。

**验收**：清单条数 N = 已核数 + 已标注暂缓数（不得有未处理项）；每个 ✅ 条目必须带**地址 + 函数名**证据；`docs/04` 与 `docs/08` 的交叉引用一致。

### 3.4 任务④ 补丁回归流程固化

**目标**：把这次的补丁应对路径写成五步清单（并尽量脚本化），下次补丁照着做。

**五步**：① dumper 重导 `data/schema/`（用 `Windows81/Il2CppDumper`，自带 exe 不支持 metadata v39）→ ② RVA 重算（任务① 的脚本）→ ③ 指纹更新（`memory_offsets.json` + `check_fingerprints`）→ ④ 实机验证（`mem_probe.py` + `memdump`）→ ⑤ 文档更新（`docs/08 §12` 类章节 + 语义别名表）。

**产出**：`docs/plan/补丁回归清单.md`（含每步的命令、判据、常见坑）；可选 `tools/scripts/patch_regression.py` 串起 ①–④ 并输出一份报告。

**验收（必须做一次反向验证）**：故意把 `memory_offsets.json` 里的 `game_assembly_sha256` 改错一位 → `memdump` 必须报「版本指纹不符」且退出码非 0 → 改回 → `memdump` 恢复退出码 0。两次输出都要贴进 `PROGRESS-补丁回归.md`。

## 4. 顺序与依赖

```
① RVA 体检 ──┐（共享「按 dump 签名匹配」能力）
             ├─→ ② 语义别名表 ─→ ③ 文档置信度升级
             └─→ ④ 补丁回归固化（把 ① ② ③ 串成清单）
```

- ① 与 ② 共用签名匹配逻辑：先做 ① 的扫描器，② 的生成器复用它。
- ③ 依赖 ②（引用语义名比引用混淆名稳定）。
- ④ 最后做，因为它把前三项的产物写进流程。

## 5. 我替领导拍的板（默认取舍，可推翻）

1. **顺序**：①→②→③→④（依赖关系见 §4）。
2. **① 先只报告、不自动改源码**：写回交给人工复核后单独提交——地址自动写错会污染全仓，报告模式风险最低。
3. **③ 的范围**：优先核与 `docs/04` 伤害链路、`docs/08 §11/§12` 相关的 🔶；其余标注暂缓。
4. **不拆并行 agent**：四项共享 `dump.cs` 与 broker 数据库，并行收益低于协调成本。
5. **文件命名**：本文 + `PROGRESS-补丁回归.md` + `BLOCKED-补丁回归.md`（沿用 `docs/plan/` 既有体例）。

## 7. 风险与回退

| 风险 | 处置 |
|---|---|
| 重算把地址写错，污染全仓 | ① 只报告不写回；写回逐文件小步提交，每步跑基线 |
| 白名单被滥用成「消除红点」 | 白名单需写明理由，命中数只许降或平 |
| broker 被重启，81 分钟分析白跑 | 开工期间不重启 broker；确需重启则先记录「当前已分析构建的 SHA」 |
| 文档批量改写引入错误 | ③ 每条独立小改，改完跑一次 docs 交叉引用检查（`docs/00-索引.md` 链接可达） |
| dumper 版本再次不满足 | 记录本次可用版本（`v20260329T093452Z`，SHA `9cad442a…`）与 .NET 8/9 前提 |
