## 6. 计算公式与逻辑

### 6.1 属性聚合（三层模型）✅ **核心**

来源：`StatusEffectController.bgh`（RVA `0x4D5E10`）+ `bgg`（RVA `0x4D5B70`）

每个 `StatType` 在 `StatusEffectController` 中维护三个字典：

| 字典偏移 | 对应 | 聚合方式 |
|---|---|---|
| `+0x38` | `Flat` | **求和** |
| `+0x40` | `PercentAdd` | **求和** |
| `+0x48` | `PercentMult` | **连乘** `Π(1+v)` |

**最终公式**：

```
                 ┌ 求和 ┐                ┌ 求和 ┐          ┌── 连乘 ──┐
Final(stat) = ( Base + Σ Flat ) × ( 1 + Σ PercentAdd ) × ( Π (1 + PercentMult) )
```

`StatModifier` 入池逻辑（`bgg` 的 `switch (Type)`）：
- `Type == 0 (Flat)` → `dictFlat[stat] += value`
- `Type == 1 (PercentAdd)` → `dictAdd[stat] += value`
- `Type == 2 (PercentMult)` → `dictMult[stat] *= (1 + value)`

**读取路径**：

```
Character.bje(stat)   ← 仅返回角色基础字段（BaseDamage/BaseCritChance/...）
        ↓
Character.bjd(stat)   = StatusEffectController.bgh(stat, bje(stat))    ← 装备/天赋/Buff 在此叠加
        ↓
Character.bjc(stat)   = clamp(bjd(stat))                               ← 对 4 个属性封顶 0.85
```

**封顶规则**（`0x4A9C30`，位掩码 `0x402010` → bit 4/13/22，加特判 37）：

| 属性 | 上限 |
|---|---|
| `CritChance(4)` | 0.85 |
| `CooldownReduction(13)` | 0.85 |
| `Dodge(22)` | 0.85 |
| `ManaCostReduction(37)` | 0.85 |

> **数值设计含义**：这是全游戏最重要的结构。堆同源百分比会**边际递减**，堆不同源则**相互乘算**。

#### 6.2.0 `bjr` —— 「倍率 × 攻强」合成（RVA 0x680400 / 0x509D80）✅ → 补丁后 `bkn` 0x18067BD00 / 0x18050E400

```
AttackScaling.wo(level) = Base + max(0, level − 1) × PerLevel            ← 0x4A9D80

Character.bjr(base, scaling) = trunc( base + scaling × Final(Damage=3) )                ← 0x680400

Player.bjr(base, scaling)    = trunc( ( base + scaling × ( trunc(Final(WeaponDamage=20)) + Final(Damage=3) ) )
                                      × ( 1 + Final(主属性)/100 ) )                     ← 0x509D80
  主属性 = STR(0)/DEX(1)/INT(2)，由 Player.fak()（0x4F3760）返回英雄职业主属性
  （GameManager+0x38 → HeroData+0x2C，Barbarian=0=力量实证；逐指令复核 2026-10-09）
  分母常量 100.0 @0x18362A370、加 1.0 @0x18362A270（均实测读出）
  游戏内力量 tooltip「当前提升 451% 伤害」= Final(力量)=451 代入本式（×5.51），与 451 逐位自洽
```

> 全程 double 运算，**只在最后 `cvttsd2si` 截断一次**（中间无舍入）；随后在 `tc` 中再截断一次
> `dmg = trunc(attackDamage × typeMul)`。`level` 来自上下文 `c.se()`（0x493B40，优先取 `Nullable<int>` 覆盖值，
> 否则回退 `Player.ffv(ability)`）。`te(h)` 不做数值合成——它把
> `(AttackScalingToken, AttackScaling)` 与 `(BaseDamageToken, LeveledFloat(BaseDamage,0))` 交给 `h.tk()`
> 用于描述/Token 解析。

#### 6.2.1 `bkn` —— 元素/物理伤害乘区（RVA `0x681280`）✅ → 补丁后 `bll` 0x18067D010

```
DamageType → StatType 映射（跳转表 RVA 0x681368）：
  Physical  → DamagePhysical (23)
  Fire      → DamageFire     (24)
  Cold      → DamageCold     (25)
  Lightning → DamageLightning(26)
  Poison    → DamagePoison   (27)
  Arcane    → DamageArcane   (28)

typeMul = 1.0 + Final(映射属性) + Final(DamagePercent=65)
```

> 汇编证据：`movsd xmm6, [1.0]` → `addsd xmm6, Final(元素)` → `addsd xmm6, Final(65)`。

> **重要**：`DamagePhysical` 等**元素属性**与 `DamagePercent`（全伤害加成）**属于同一加算池**。这解释了为什么面板上"物理 312.4% + 全伤害 88.3%"实际是 `×5.007`，而不是 `×4.124 × 1.883`。

#### 6.2.2 `bko` —— 条件伤害加算池（RVA `0x681380`）✅ → 补丁后 `blm` 0x18067D160（条件判定已抽为独立谓词 `fji` 0x18050A860）

返回 `1 + Σ`，各项判定条件：

| 条件（读目标状态） | 判定依据 | 加入属性 |
|---|---|---|
| 目标 HP 比例 **> 0.8** | `comisd 0.8` | `DamageVsHealthy(29)` |
| 目标 HP 比例 **< 0.3** | `comisd 0.3` | `DamageVsInjured(30)` |
| 目标被减速 | `Character.bkb()` | `DamageVsSlowed(31)` |
| 目标被定身 | `bkd() \|\| bke()` | `DamageVsImmobilized(43)` |
| 目标流血 | `bkj(self,target)` | `DamageVsBleeding(45)` |
| 目标中毒 | — | `DamageVsPoisoned(46)` |
| 目标灼烧 | — | `DamageVsBurned(63)` |
| 远程命中 | — | `DamageVsDistant(58)` |
| 目标为精英 | — | `DamageVsElite(32)` |
| 目标处于易伤状态 | `SEC[+0x60]` 标志 | `VulnerableDamage(40)` |

> 汇编特征：入口 `movsd xmm6, 1.0`，其后**全部为 `addsd`**，无任何 `mulsd` → 铁证为**同池加算**。

> **词条池对照**：`ItemizationConfig.ConditionalDamage` 表（SHA-256 校验）= `[29,30,31,32,40,43,45,46,62,63]`，
> 与 `bko` 的运行时检查集相差一项 —— 表内含 `DamageOverTime(62)`、不含 `DamageVsDistant(58)`；
> 58 由 `bko` 的 0x681858 分支（远程命中）单独读取。即：**词条可滚出的条件伤害集合 ≠ 运行时逐项检查集合**。

#### 6.2.3 暴击（RVA `0x680140` / `0x681090` / `0x494520`）✅

```
# 暴击率（bjl，0x680140）
critFromStats = clamp(Final(CritChance), 0, 0.85)

# 完整暴击率（bkk，0x681090）
critChance = clamp( bjl() + SEC.bgm(target) + bkl(target, ability) , 0, 0.85 )
                                    ↑ 状态行为暴击   ↑ 装备/天赋条件暴击

# SEC.bgm（0x4D65B0）：Σ 生效状态行为 Slot16 yi(bk, target)（基类默认 0x4B0C40 返回 0；
#   实例：SourceCritChanceBonusBehavior.BonusCritChance @0x4B0550）
# Player.bkl（0x505860，覆写 Slot 14）：fgw(ability) + Σ nub[(条件,加成)]
#   + Σ nud[(条件, 状态, 加成, 技能, Tag)]（fgl 判状态 + bb.wf 匹技能），
#   条件 = TargetStateCondition{Vulnerable, Stunned, Slowed, Elite, Immobilized, SpecificStatus, Distant}
# Character.bkl 基类（0x4B0C40）= 0

# 暴击伤害加成（0x494520）
critDamageBonus = 0x4942D0()              # = Final(CritDamage)
                + 装备/天赋加成
                  ↓ 经 Character.bkm(float)
critMultiplier  = 1 + critDamageBonus

# 最终（DamageEffect.te）
dmg = crit ? dmg × (1 + critDamageBonus) : dmg
```

> 面板 381.2% 暴伤 → 暴击时 `×4.812`，独立乘区。

#### 6.2.4 减伤（RVA `0x682150` / `0x6821F0`）✅

```
# 护甲/魔抗曲线（bkt）
resist    = (damageType == Physical) ? Final(Armor) : Final(MagicResist)
L         = max(1, attackerLevel)
armorResist = resist / (resist + 50.0 × L)          # 常量 50.0 @ 0x18362A350

# 元素与全局减伤（bku 跳转表 RVA 0x682384）
Physical  → PhysicalDamageReduction (51)
Fire      → FireDamageReduction     (52)
Cold      → ColdDamageReduction     (53)
Lightning → LightningDamageReduction(54)
Poison    → PoisonDamageReduction   (49)
Arcane    → ArcaneDamageReduction   (55)

final = dmg × (1 − armorResist) × (1 − clamp(elemRed,0,1)) × (1 − clamp(DamageReduction,0,1))
```

**减伤侧特性**：三项减伤为**乘法叠加**，因此互不稀释，堆任何一项都线性有效；护甲为**递推曲线**，收益递减。

#### 6.2.5 易伤（Vulnerable）✅

| 机制 | 效果 | 位置 |
|---|---|---|
| 固定乘区 | `dmg × 1.3` | `bkq` 步骤 8，常量 `1.3` @ `0x18362A288`（补丁后：`blo` `0x18067DBB0`，常量 `1.3` @ `0x18363F058`） |
| 条件加算 | 攻击方 `VulnerableDamage(40)` 计入 `bko` 池 | `bko` |

> 两者**同时生效**：挂上易伤 → 全伤害 ×1.3；若攻击方有"对易伤敌人伤害 480%"，则条件池再 `×(1+4.801+…)`。

#### 6.2.6 面板「坚韧度」换算（✅ 非战斗链路，UI 口径；2026-10-10 REA 反编译复核）

面板与详情页的防御类评分由 `EquipmentUI` 单独计算，**不参与战斗伤害结算**：

```
// EquipmentUI.gdy() —— 补丁后 RVA 0x567B20 / VA 0x180567B20
// REA 反编译原文（FUN_180567b20，2026-10-10 本轮复核）：
//   iVar4 = FUN_1804548a0(&local_58, 0);        // ACTk ObscuredInt 解码出等级（见 aliases.json）
//   if (iVar4 < 1) iVar4 = 1;                   // ← max(1, level) 兜底
//   fVar6 = (float)FUN_18067bae0(lVar1, 0);     // ← (1 - dr)
//   return 1.0 / ((1.0 - (double)fVar6) *
//                 (1.0 - ((double)(float)dVar3 / ((double)(float)dVar3 + (double)iVar5 * 50.0) +
//                         (double)(float)dVar7 / ((double)(float)dVar7 + (double)iVar4 * 50.0)) * 0.5));
等价写法：return 1.0 / ( (1.0 - dr) * (1.0 - ( rA/(rA + lvlA*50.0) + rB/(rB + lvlB*50.0) ) * 0.5) );
```

- 抗性曲线沿用与 §6.2 步骤 10 相同的 `r / (r + 50 × level)` 形式（常量 `50.0` 同址 `0x18363F120`），`level` 经 `max(1, level)` 兜底
- 两条曲线按 `0.5` 平均后与 `(1 − dr)` 相乘再取倒数 —— 这是「有效生命 / 坚韧度」口径（伤害承受倍率）
- 同类面板评分还有 `EquipmentUI.gdw()`（`0x180567670`）与 `gdx(ValueTuple<StatType,double>[] weights)`（`0x180567A10`），
  配套三张带权重的属性表 `ona`/`onb`/`onc`（`[TupleElementNames({"Stat","Weight"})]`）与常量 `ond = 0.25`

> **易混淆点**：战斗侧护甲曲线（§6.2 步骤 10）与 UI 侧此换算式形似而用途不同；`docs/08 §12.4` 亦记有该差异。

#### 6.2.7 技能类型乘区（Slot 16）与 DOT 乘区 —— ✅ 2026-10-12 REA 新证

§6.2 图里的步骤 1–6 之外，还有两处**按技能类别**的乘区，补丁前文档未记录：

```
# 技能类型乘区：Character.SkillTypeDamageMultiplier(AbilityData)（Slot 16；语义名见 aliases.json）
tags = AbilityData.Tags                       # List<AbilityTag>，字段 +0x28
mul  = 1.0 + (tag 含 BasicAttack(0)  ? Final(BasicAttackDamage   = 33) : 0)
           + (tag 含 StrongAttack(1) ? Final(StrongAttackDamage  = 34) : 0)
           + (tag 含 Special(2)      ? Final(SpecialAbilityDamage = 61) : 0)
# 应用点：DamageEffect.tp 内 `dmg *= mul`（vtable Slot 16 调用）
```

> **不是 if/elif 单选**：三项判定彼此独立、命中即 `addsd` 累加（初值 1.0）——多标签技能（同时带
> BasicAttack 与 StrongAttack）两项都吃；`Special(2)` 的 61 此前在工具里被完全忽略，特殊技能一直少这一项。
> AbilityTag 枚举见 `dump.cs`：BasicAttack=0 / StrongAttack=1 / Special=2（None=9999）。

```
# DOT 乘区：DamageOverTimeBehavior.TickDamage(Character, double)（语义名见 aliases.json）
tickDmg = baseDamage × scaling × ( Final(DamageOverTime = 62) + Character.ElementDamageMultiplier(DamageType) )
```

> **62 与元素乘区同池加算**（`addsd`，不是相乘）；62 **不在**直击链路里：`bko`（条件池）与
> `SkillTypeDamageMultiplier` 都不读它——`bko` 的运行时检查集是 {29,30,31,43,45,46,58,63,32,40}
> （含 58、不含 62），与 `ItemizationConfig.ConditionalDamage` 词条池 {…,62,…} 的差异由此坐实。

**工具已建模 DOT（2026-10-16）✅（池口径）/🔶（频率口径）**：`DamageOverTimeBehavior` 是
StatusEffectData 的一种 Behavior（字段 `DamagePerTick@0x10`/`DamageType@0x14`/`CanCrit@0x18`/
`ReapplyMode@0x1C`），技能经 `ApplyStatusEffectEffect.StatusEffect.pathID` 引用之。玩家侧
DOT 状态：`Bleeding`（0.5×武器伤害/跳·TickRate 1.0·持续 5s·物伤·不暴击·Pooling）、`Burn`、
`HunterPoison`，分别由 WarriorBasicAttack3/HeavyAttack4、SorcererSpecial4/StrongAttack1、
HunterBasicAttack1/HeavyAttack4/Special1 施加。

落地：`gamedata.dot_specs/ability_dot`（数据层原值）+ `engine.DamageModel.dot_tick_damage`
（`tick = (元素乘区 + Final(62)) × base × 条件池 × 暴击`，减伤层与直击同 `ApplyDamage` 收口），
在 `skill_service` 折入该技能秒伤：多重量 `min(上限, 每秒施放次数 × 持续)`（非叠层上限 1）。
回归断言：内核「62 同池加算 → tick ×2」「吃条件池 ×1.5」「暴击按目标 60 折减」；
GUI「注入 62 只命中 DOT 技能（WarriorBasicAttack3/HeavyAttack4，自证二者确为 DOT 施加者）」。

> **口径收口（2026-10-16 续）✅/⚠️**：tick 链完整形态（`yp`/Slot 5 反汇编 + live 读 klass 槽解析）为
> `tick = round( 实例 lxt × 条件池 × max(1, 叠层) × 实例 lxp × 暴击 )`：
> · `lxt` = apply 时由 `yt` 算好的每跳基础（= (62 + 元素乘区) × base）；
> · **条件池** = `Character.ConditionalDamagePool`（`blw`）——live 读 `.Player`/`.Enemy` 的 klass+0x228
>   得 `Player$$blw`/`Character$$blw`，实锤（已并入工具）；
> · **叠层** = `bl.lxn`@0x28，`max(1, ·)` 相乘——`min(MaxStacks, 施放频率 × 持续)`，非叠层封顶 1（已并入）；
> · **暴击** = `1 + 暴击率 × (1 − clamp01(目标 Final(60))) × (Final(5)+暴伤加成)`，CanCrit 时（`ys` 反汇编，已并入）。
> **边界已定（2026-10-16）**：实例倍率 `bl.lxp`@0x30 在 `.ctor` 与 apply（`StatusEffectController.bgw`）
> 两处均写死 `1.0f`、其它状态方法无写入 → lxp ≡ 1.0（工具一致）；技能类型标签乘区 33/34/61 **不**参与
> DOT——tick 的 vtable+0x228 已证实是**条件池**（`blw`），标签乘区只在直击 `DamageEffect` 应用点生效。
> （`bl.lxn` = `max(1, 调用方 int)`：`StatusEffectController.bgw` **不累加**——每次 apply 新建实例，
> reapply 分支为「跳过（`bl.lxj` ≥ 新值）或移除重建」；累加发生在调用方，而 apply 方法**无直接调用点**
> （经方法指针/元数据在运行时解析，静态不可达）。故叠层口径按「并存实例数 = `min(MaxStacks, 施放频率×持续)`」稳态近似。）
>
> **实机实证（2026-10-16，训练假人，✅）**：活体读 `Character+0x130 → StatusEffectController.lyk`，假人身上 3 个
> `bl`；其中由玩家施加（`lxq`=玩家）的 **Bleeding** 实例：`lxj`(剩余)=**4.547** / `lxk`(最大)=**5.000**
> （= `StatusEffectData.Duration`）、`lxn`=**1**、`lxp`=**1.0000**、`lxt`=**133440.0**（apply 时算好的**每跳伤害**，
> 即 `yt` 的结果；同表另有一非伤害状态 `lxt`=0.0）。玩家侧另见 `lxn`=**10** 的叠层 buff → **`lxn` 即叠层数**
> （apply 时由调用方一次性传入，bgw 自身不累加）。故非叠层（Bleeding=Pooling）为单实例、`lxn`=1；
> 叠层（Stackable）为 `lxn`=累计数——工具的 `min(MaxStacks, 施放频率×持续)` 即该叠层数的稳态估计。

#### 6.2.8 最终减伤（`StatType.FinalDamageReduction = 66`，1.0.3 新增）✅

**指令级证据（2026-10-16，capstone 直读 `GameAssembly.dll`；当期类/方法名见 `aliases.json`）**：

`Character.ApplyDamage`（1.0.3 `bme` @ `0x1806893E0`）尾部（`0x1806894A0`–`0x1806895E4`）：

```
; rbp = 传入伤害；ebx = 伤害类型
call Character.ArmorCurve(rdi, ebx, esi, 0)                ; @0x180689360 → armorResist
xmm8 = 1.0 − armorResist ; × (double)rbp                   ; = 伤害 × (1−护甲减伤)
switch(damageType) → ebx = 0x31/0x34/0x35/0x36/0x37 …      ; 映射到元素减伤 stat(49/52/53/54/55…)
xmm10 = (1.0 − clamp01(Clamp(Final(ebx)))) × xmm8          ; × (1−元素减伤)
xmm6  = (1.0 − clamp01(Clamp(Final(64))))  × xmm10         ; × (1−全局减伤)
xmm7  = Clamp(Final(66))   （non-finite → 0；GetCap 落 inf → 无上限）
xmm6  = xmm6 − xmm7                                        ; ★ 乘区之后的一次「绝对减法」
return max(0, trunc(xmm6))                                 ; 下限 0
```

**结论**：

```
final = max(0, trunc( 伤害 × (1−护甲减伤) × (1−clamp(元素减伤,0,1)) × (1−clamp(全局减伤,0,1)) − Final(FinalDamageReduction) ))
```

- `FinalDamageReduction` 是**受击方的绝对量**（单位同伤害），不与三项减伤的乘法层叠加，而是在其后一次性扣减；**无上限**
  （`StatCap.GetCap` 的 `cmp ecx,0x40; jne → inf` 分支，见 `docs/08 §14.3`）。
- 因此它**不进攻击方的 DPS 倍率**：`deskrawl_calc` 建模为 `Target.final_damage_reduction`，只在绝对伤害 / `effective_dps`
  上做减法（保底 1/击）；条件池与乘区倍率（`expected_mult`）不含它。
- 1.0.3 数据落点：新传奇护腿 `LegendaryPants4` 的 `EquipmentEffect_StatModifier` 以 Flat 给 300
  （`data/so_dump/EquipmentEffects.json`，`_pathid 4905`）。

> 与另两项减伤的差别：元素减伤 / `DamageReduction(64)` 经 `StatCap.Clamp` 后再 clamp 到 `[0,1]`（百分比口径），
> 而 66 只经 `Clamp`（无上界）并按**绝对值**扣除。

### 6.3 装备/宝石/符文数值

```
# 宝石（GemData : ItemData）
GemData 继承 StatModifier 语义：Stat + Modifier + Value（固定值，不随等级）

# 符文（RuneData : ItemData）
RuneData 的 Value 是 LeveledFloat → 随符文等级成长
  value(runeLevel) = Base + max(0, runeLevel − 1) × PerLevel

# 符文套装（RuneSetData）
达到 RequiredCount 后：
  · 注入 Modifiers : StatModifier[]
  · 注入 Effects : EquipmentEffectBehavior[]
  · 授予 AbilityLevels : AbilityLevelGrant[]

# 装备固定属性（ItemData.FixedStats : StatModifier[]）
# 装备特效：EquipmentEffectBehavior 子类在运行时产出 IEnumerable<StatModifier>
#   - EquipmentEffect_AllStats：对 Core = {Str, Dex, Int} 三项各 +Bonus
#   - EquipmentEffect_StatConversion：TargetStat += SourceStat × Fraction
#   - EquipmentEffect_StatPerStatusStack：Stat += ValuePerStack × 状态层数
```

**词条生成规则**（`ItemizationConfig`）：

```
SlotPools[slot] → { Primary: List<StatType>, Secondary: List<StatType> }
GemSocketsBySlot[slot] → MaxSockets
MinLevelForSockets → 解锁孔位的最低物品等级
```

> ✅ `Primary`/`Secondary` 对应 `AttributeCategory.Primary/Secondary`；方法 `cei(SlotAffixPool, List<StatType>, AttributeCategory)` 负责按类别归集。

**词条数值 Roll 公式** ✅（`gg.dna` RVA `0x76F5F0` / `gg.dnt` RVA `0x771590` / `gg..cctor` RVA `0x771DC0`）

```
perLevel[stat] = 系数表（55 项）                  ← Dictionary<StatType,float>
base           = itemLevel × perLevel[stat]      (+5 当 stat == WeaponDamage(20))
rollFactor     = 1.15（取最大） 或 Random(0.85, 1.15)（正常掉落）
rarityMul      = { Common:+0.2, Uncommon:+0.4, Rare:+0.5, Legendary:+0.6, 其他:+0 }
value          = (1 + rarityMul) × base × rollFactor     → 保留 3 位小数；下限 0.001
```

**技能伤害倍率** ✅（`DamageEffect`，取自 `[SerializeReference]` 载荷）

```
倍率(level)   = AttackScaling.Base + max(0, level − 1) × AttackScaling.PerLevel   ← wo() 0x4A9D80
attackDamage  = 攻击者.bjr(BaseDamage, 倍率)                                      ← 合成见 6.2.0
                Player:    trunc( (BaseDamage + 倍率 × (trunc(Final(WeaponDamage=20)) + Final(Damage=3))) × (1 + Final(主属性)/100) )
                Character: trunc( BaseDamage + 倍率 × Final(Damage=3) )           ← 敌人等非 Player
```

> 技能伤害同样吃**乘区 A/B/C**（`tc` 内 `×bkn` → 暴击 → `×bko`）。技能链式结构示例：`SpawnParticleAoEEffect`（Lifetime/RehitInterval）→ 内嵌 `DamageEffect` + `ApplyStatusEffectEffect`。

## 7. 属性关联关系与依赖

### 7.1 伤害乘区拓扑图

```
                      ┌──────────── 独立乘区（相互相乘） ────────────┐
BaseDamage(技能) ──×── 攻强/等级成长 ──×── 【乘区A】元素+全伤害 ──×── 【乘区B】暴击 ──×── 命中浮动 ──×── 【乘区C】条件伤害池 ──×── 【乘区D】易伤 1.3
                                                                                                                    ↓
                                                         ┌──────────── 减伤层（乘法） ────────────┐
                                            (1 − 护甲曲线) × (1 − 元素减伤) × (1 − 全局减伤)
```
其中：
- **攻强合成（bjr）** = `(BaseDamage + 倍率 × (武器伤害(20) + 通用增伤(3))) × (1 + Final(职业主属性)/100)`
  —— 主属性乘子在攻击伤害内，**不在乘区 A–D 中**（工具链的 DPS 口径同此）
- **乘区A（同池加算）** = `1 + Damage<type> + DamagePercent`
- **乘区B** = `1 + CritDamage + 装备/天赋暴伤`（仅暴击时）
- **乘区C（同池加算）** = `1 + Σ 10 项 ConditionalDamage`
- **乘区D** = 固定 `1.3`

### 7.2 属性 → 数值系统依赖表

|---|---|---|
