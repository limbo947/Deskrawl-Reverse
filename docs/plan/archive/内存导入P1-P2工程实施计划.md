### 2.1 已实测验证的能力（可直接复用，来自 `tools/scripts/mem_probe.py` 与调研报告 §3）

| 能力 | 状态 | 关键事实 |
|---|---|---|
| 只读进程通道 | ✅ 实测 | `OpenProcess(0x0410)` + `ReadProcessMemory`，无反调试 |
| 单例定位链 | ✅ 实测 | 静态 getter（rip 相对扫）→ 元数据槽 → `Il2CppClass`（name char* @+0x10 自校验）→ `static_fields@+0xB8` → 实例（klass 回指自校验） |
| 锚点 RVA | ✅ | `GameManager.diw()=0x75B860`、`Inventory.eyy()=0x4EFDA0`、`Storage.fmq()=0x51CA20`、`SaveSystem.ebr()=0x79DBC0` |
| Player 获取 | ✅ | GameManager+0x40 → PlayerCombatController+0x20（进图态）；**GameManager+0x48 → PlayerTownController+0x20（城镇态，dump.cs L395639，待接入）** |
| ACTk 解码 | ✅ 全类型 | Int/Long：`(hidden−key)^key`；Float：`bswap12(hidden)^key`；Double：字节置换（swap01 + 4→5→7→4 三循环）后 `^key`（jxh@0x453B70）；密钥内嵌结构体 |
| IL2CPP Dictionary | ✅ 实测 | `entries@0x18`、`count@0x20`；Entry 步长 **0x38**：`next@0, hash@4, key@8, value@0x10`（ObscuredDouble 0x28：hash/hidden/key/fake/oldByte8） |
| 聚合字典 | ✅ 实测（⚠️ 代码未沉淀） | Player +0x218/0x220/0x238/0x240/0x278/0x280/0x288 共 7 个 `Dictionary<StatType, ObscuredDouble>`，交互式 spike 已解码出真实面板（力量 360、生命 4200、暴击 0.215…），但遍历代码未沉淀进任何脚本（mem_probe.py 无 Dictionary 实现）→ **M2-0 先补齐，否则 §6.2 对拍无基准**（§5） |

## 3. Proposed Changes

### 3.0 架构总览

```
tools/deskrawl_gui/core/
├─ memory_offsets.json          ← 全部 RVA/偏移/特征串 + GameAssembly SHA-256（P2 生效）
└─ memory_import.py             ← 自包含只读导入（约 380 行，仅 ctypes+struct+json）
     ├─ ProcessReader           OpenProcess/ReadProcessMemory/模块基址（只读两 API，硬约束）
     ├─ Il2CppReader            String/Array/List/Dictionary 基元 + klass 类名校验
     ├─ ActkCodec               obsc_int/long/float/double（§2.1 公表算法）
     ├─ Locator                 getter 扫描 → klass → static_fields → 单例（三重自校验）
     ├─ SnapshotBuilder         Player/Inventory/Storage/聚合字典 → dict 快照 + 校验（结构/值域/双读一致）
     └─ import_snapshot() -> SnapshotResult（含时间戳、来源模式 α/β、告警列表）
tools/deskrawl_gui/core/profile.py   ← +from_snapshot()（约 +60 行）
tools/deskrawl_gui/app.py            ← 菜单启用 + 导入对话框 + 错误态（约 +80 行）
```

设计约束（继承 GUI v1）：`deskrawl_gui` **不 import `tools/scripts/`**（memory_import.py 自包含，
mem_probe.py 保留为独立诊断工具，两者允许 ~120 行算法重复，各自演进）；`deskrawl_calc` 零改动；
每文件 ≤800 行（目标 ≤400）。**拆分预案**：`memory_import.py` 实质超 400 行时拆
`memory_reader.py`（ProcessReader/Il2CppReader/ActkCodec 三层）+ `memory_import.py`
（Locator/SnapshotBuilder/CLI），不硬撑单文件——380 行估算偏乐观（mem_probe 已有 473 有效行，
其中约半数为诊断打印不需搬运，但 Dictionary 遍历/双态 Player 链/offsets 加载/校验重试均为新写）。

### 3.1 快照数据模型（`SnapshotResult.payload`）

```python
{
  'meta': {'time': ..., 'mode': 'alpha'|'beta', 'pid': ..., 'warnings': [...],
           'hero': '角色名/槽位ID（SaveSystem.nfk 槽位摘要，防切角色后用过期快照静默错配构建）'},
  'player': {'level': 70, 'base': {StatType: float, ...},   # ← 聚合字典 nsq（Final 面板）
             'pools': {'flat': {...}, 'pct_add': {...}, 'pct_mult': {...}},  # 其余字典（语义 M2 标注）
             'town_mode': bool},
  'inventory': [{'uid': ..., 'item': <ItemData pathID 反查名>, 'count': ...}, ...],
  'storage':  [...],
  'equipment': [...],    # 仅 β 模式（M1 spike 定位成功时）
}
```

### 3.2 `profile.from_snapshot()`（α/β 双模式）

- **α 聚合快照模式（保底，M2 交付）**：`base` = 导入的 Final 面板聚合值；装配列表为空。
  用途：候选排序（基线=当前完整构筑，候选=基线+单件增量）。
  **精度边界（须写入 UI 提示）**：Final 填入 base 抹掉了三层聚合的池结构——**Flat 类词条**
  （固定生命/护甲/固定增伤等）的 Δ 严格正确；**%Add/%Mult 类词条**的 Δ 为近似值
  （真实 flat/add/mult 池分布未知），增量方向必正确但幅度不保证。α 模式下排序视图须标注
  「百分比类词条增量为近似」。
  装备对比的「当前武器」侧不可分解 → 对比视图降级为「基线 vs 基线+候选词条」。
- **β 逐件导入模式（目标，视 M1）**：定位装备容器后，逐件还原武器/防具词条 →
  填充 `weapon_current` 与 `assembled`，完整复刻 cli.demo 装配链，装备对比全功能可用，
  并可用游戏聚合字典做**逐 StatType 对拍校验**（GUI 装配结果 ≡ 内存聚合值）。

### 3.3 ItemUid 反查（静态，零内存依赖）

`ItemUid/ItemName → data/so_dump/ItemData.json`（GUI 已内置 GameData 加载器，加一个
uid→name 索引即可）；仓库 95 件实测 GUID 可作为反查自测数据。

### 3.4 M1 spike：装备容器定位（半天级，决定 α/β）

按序尝试，任一命中即停：
1. **UI 反查**：用现成 `tools/scripts/xref.py` 反查角色面板/背包 UI 类的 InventorySlot 数据源
   （`dump.cs` 中 UI 类持有 `Dictionary<EquipSlotType, ...>` 或装备槽位数组的可能性最高）；
2. **填充链反查**：xref `Player.nwo`（List<StatModifier> @0x518）的写入方法，回溯其入参容器；
3. **枚举兜底**：进图前后对比 Inventory.nso 数组内容差异（装备是否内嵌保留索引）。
4. 全部失败 → 固化 α 模式交付，β 留待下版本（不阻塞 M2/M3）。

### 3.5 GUI 集成（M3）

- 主菜单「数据导入」→「从运行中的游戏导入（只读）…」：导入前探测进程/登录态，结果对话框
  显示快照时间、模式（α/β）、物品件数、告警；
- 导入成功 → `profile.from_snapshot()` → 走既有 `profileChanged` 刷新链；
- 错误态（中文提示，不崩溃）：游戏未运行 / 已运行但未加载角色（单例为 null）/ **权限不足**
  （游戏以管理员运行而 GUI 非管理员 → `OpenProcess` 失败，提示以管理员身份重启 GUI）/
  **Python 位数不符**（32 位解释器读不了 64 位进程，导入前预检 `struct.calcsize('P')`，不符即拦截）/
  版本指纹不符（P2）/ 读取校验失败（撕裂读，自动重试 3 次后提示重试）。

### 3.6 P2 健壮化（M4）

- GameAssembly.dll + global-metadata.dat SHA-256 指纹写入 `memory_offsets.json`，失配即禁用菜单并提示重新导出 schema；
  连带记录 `data/so_dump/ItemData.json` 的条目数与生成时间戳，指纹失配时一并提示重新导出 so_dump
  （防 ItemUid 反查基于过期静态数据静默错位）；
- 快照时间戳常驻状态栏；导入节流（≥1s，手动触发为主）；
- 只读硬约束写入模块 docstring 并在代码评审 checklist 固化：禁止 `WriteProcessMemory`/
  `CreateRemoteThread`/注入/挂起线程。

## 4. Assumptions & Decisions

| 决策 | 结论 | 理由 |
|---|---|---|
| 实现语言/依赖 | 纯 ctypes+struct（stdlib） | P0 已验证可行；GUI venv 零新依赖 |
| 代码归属 | 自包含于 deskrawl_gui/core | GUI 不依赖逆向脚本的约束；scripts 侧 mem_probe 保留 |
| 路径 | 仅路径 B（运行时单例） | 路径 A/C 已被 P0 证伪 |
| 模式 | α 保底 + β 目标，M1 spike 定夺 | 装备容器是唯一未知项，不让它阻塞交付 |
| 聚合字典语义 | M2 用 UI 对拍标注 | 解码已通，只差命名 |
| 触发方式 | 手动菜单触发（v1 不做后台轮询） | 撕裂读与性能风险最小化 |
| 反作弊边界 | 只读两 API 硬约束 + 文档/评审固化 | 调研报告 §5.1/§5.4 |
| 版本漂移 | 指纹校验 + 运行时三重自校验（类名/klass 回指/值域） | 双保险：偏移错→校验失败→明确报错而非脏数据 |
| 行数 | memory_import.py ≤400 行，超限拆 memory_reader.py | 项目 800 行硬上限留余量（棘轮规则） |
| 语言 | 界面与错误提示全中文 | 与 GUI v1 一致 |

## 5. 开发顺序（里程碑）

> 工期为单人全职估算。**关键路径**：M1 → M2（最长）→ M3 → M4；M1 失败不阻塞 M2（α 固化保底）。

1. **M1 装备容器 spike（0.5 天）**：§3.4 三策略 → 产出「β 可行 + 容器偏移」或「α 固化」结论，回填本文档。
2. **M2 导入核心（2–3 天）**：
   - **M2-0 字典遍历沉淀（前置，约半天）**：先把 IL2CPP Dictionary 遍历（Entry 0x38 /
     ObscuredDouble 0x28）补进 `tools/scripts/mem_probe.py`，输出 7 个聚合字典全量 KV——
     §6.2 的对拍基准，未做则 M2 验收不可执行；
   - `memory_import.py` 五层（Reader/Il2Cpp/Codec/Locator/Snapshot，含双读一致性校验）+
     `memory_offsets.json`；
   - 接入城镇态链 `PlayerTownController`（GameManager+0x48，dump.cs L395639），进图/城镇双态均可导入；
   - CLI 冒烟：`python -m deskrawl_gui.memdump`（或脚本参数）打印快照，与 mem_probe 逐项对拍。
3. **M3 GUI 集成（1 天）**：菜单 + 错误态（六场景，§3.5）+ `from_snapshot()` + 面板/属性表填充 +
   α 模式候选排序验证（含「百分比类词条增量为近似」UI 标注，§3.2）。
4. **M4 健壮化（P2，1 天）**：指纹（含 so_dump 联动）、重试、时间戳、错误态完善 + 全量验收。

## 6. Verification

1. **内核回归**：`python -m deskrawl_calc.cli selftest` 8 项 PASS（内核零改动）。
2. **解码对拍**：memory_import 快照的 level / BaseMaxHealth / Storage 件数与 `mem_probe.py` 输出一致；
   7 个聚合字典全量 KV 与 mem_probe（M2-0 沉淀后）逐项一致；
   ACTk 四类型解码各有 ≥1 个已知值锚点（level=70 类）。
   **双态用例**：进图态（PlayerCombatController）与城镇态（PlayerTownController）各导入一次，
   均成功且 level 一致。**双读一致性**：同一会话连续导入两次，聚合字典全键值与物品 UID 列表逐值相等。
3. **β 模式逐项对拍（若 M1 命中）**：GUI 装配后 stat_table 的 Final 值 ≡ 内存聚合字典 `nsq` 值
   （字典全部键逐项比对，误差 0——同一 double；键数以导入时实际键集为准并记入快照 meta）；
   不等则装配链有缺口，必须查清后才算过。
4. **α 模式语义对拍**：候选排序基线 = 导入快照 DPS。任取 3 个候选：**≥1 个 Flat 类词条**
   （如固定生命/护甲）的 Δ 与手工直算误差 <0.5%；百分比类词条仅要求增量方向一致
   （幅度失真为已知边界，§3.2）。
5. **GUI 冒烟**：`--selftest` 14/14、`--smoke` 退出码 0 不回归。
6. **错误态五场景**：游戏未运行 / 未加载角色 / 权限不足（管理员游戏 + 非管理员 GUI）/
   Python 位数不符（预检拦截）/ 指纹不符 → 均中文提示且不崩溃。
7. **只读审计**：`memory_import.py` 与 GUI 包全局 grep 无 `WriteProcessMemory|CreateRemoteThread|
   SuspendThread|VirtualProtect|LoadLibrary` 远程调用（验收门禁，**必做**：一行脚本进 CI 或预提交钩子）。
8. **行数检查**：新文件 ≤800 行（目标 ≤400）。

## 7. 风险与回退

| 风险 | 缓解 |
|---|---|
| M1 三策略全部落空 | α 模式保底交付（候选排序完整可用），β 降级为下版本 |
| 聚合字典语义标注不准 | 值域合理性 + 游戏内 UI 人工对拍；语义只影响展示命名，不影响数值 |
| 游戏更新 | 指纹拦截 + 重跑 Il2CppDumper/mem_probe 再生（工具链现成） |
| 撕裂读 | 单遍快照 + 结构/值域校验 + **双读一致性**（拦截「值域内的并发修改」，如力量 360→361）+ 3 次重试 + 择时（城镇/菜单） |
| 权限/位数环境 | 启动预检：管理员游戏需管理员 GUI（OpenProcess 失败 → 明确提示）；64 位 Python 硬要求，32 位预检拦截 |
| so_dump 静态数据版本漂移 | ItemUid 反查基于 so_dump 快照；指纹失配时连带提示重新导出 so_dump（§3.6） |
| 跨角色快照错配 | meta 记录角色名/槽位 ID（SaveSystem.nfk），GUI 展示快照来源，切角色后提示重新导入 |
| 合规 | 只读、只导入自己账号、功能手动触发、界面免责提示（继承调研报告 §6） |
