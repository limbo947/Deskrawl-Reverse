## 8A. 实测数值（解码结果）

> 本节全部数据来自 `[SerializeReference]` 之外的字段**字节级精确解码**（1333 个实例、0 错误）。
> 解码器规则：ScriptableObject payload 同样带 `m_GameObject`(12) + `m_Enabled`(1+3pad) + `m_Script`(12) + `m_Name` string 前导头；字段按 C# 声明顺序、基类优先；**全部字段按 4 字节对齐**（含 `long`/`double`，即 `ALIGN8 = false`）；`ObscuredFloat=28B`、`ObscuredInt=12B`、`ObscuredLong=20B`，明文 = `hiddenValue XOR currentCryptoKey`。

### 8A.2 成长曲线实测值 ✅

```
敌人成长（每级乘算系数）
  Retail:  Lv 0–30   HP ×1.12/级   DMG ×1.10/级
           Lv31–50   HP ×1.08/级   DMG ×1.04/级
           Lv51–70   HP ×1.06/级   DMG ×1.03/级     ← 明显三段递减
  Beta:    三段均为 HP ×1.12 / DMG ×1.10（未做递减，说明 Beta 是早期版本）
      （字段名义值为 0.12 / 0.10，实际为「每级 +12% / +10%」的乘算系数）

经验
  XpPerBaseHealth = 1.0        → 经验 ≈ 敌人基础生命 × 1.0
  XpPerLevelScale = 0.10
  XpZeroUnderLevel = 6         → 等级差 ≥ 6 时经验为 0

技能等级
  MaxAbilityLevel        = 10
  AbilityBaseXPToLevel   = 135（1→2 级所需）
  AbilityXPGrowthPerLevel= 1.5

符文等级
  MaxRuneLevel           = 6
  RuneBaseXPToLevel      = 450
  RuneXPGrowthPerLevel   = 1.8

Paragon（Retail 与 Beta 相同）
  ParagonMobsToLevelKnots   = [(1,56063), (10,63212), (20,184023), (50,242191),
                               (200,242191), (300,568377), (400,779240), (475,1745254)]
  ParagonMobsGrowthPastLastKnot = 12880
  ParagonPointsPerLevel     = 1

挂机（Offline）
  OfflineMobsPerHourKnots = [(5,70), (20,470), (40,470), (60,690)]
  OfflineMobsPerGoldRoll  = 4.0
  OfflineTimeCapHours     = 8.0（基础 8 小时）
```

> **数值设计观察**：Paragon 曲线在 50→200 级之间**完全平段**（242191 重复），说明设计上刻意把中段做成"高原期"，配合 300/400/475 的三个陡增节点形成后期驱动力。挂机 20→40 小时也是平段。

### 8A.3 强化与打孔实测值 ✅

```
MaxEquipmentUpgradeLevel = 12
UpgradeSuccessChances    = [1.0, 1.0, 1.0, 1.0, 0.75, 0.5, 0.4, 0.3, 0.2, 0.1, 1.0, 1.0]
                                                        ↑ +4 后开始衰减   ↑ 后两级回满(特殊强化)
SocketMaterialAmount     = 100      （打孔消耗材料数量）
SocketGoldPerItemLevel   = 400      （打孔金币 = 400 × 物品等级）
TalentRefundCostPerPointSpent = 8   （洗点单价）

UpgradeRecipes（GameConfig.UpgradeRecipes@0x58，List<EquipmentUpgradeRecipe>，按稀有度索引）
  Common(0)         → Recipe#60388
  Rare(2)           → Recipe#60391
  Legendary(3)      → Recipe#60390
  Divine(4)         → Recipe#60389
  （Uncommon(1) 在列表里没有条目——按稀有度精确匹配找不到配方）
SpecialUpgradeRecipe（独立字段 @0x68，不是列表第 5 项）= Recipe#60392（200 万金 + 材料#59921）
ExtraUpgradeMaterials（@0x60，按槽位索引的额外材料）

SalvageYields（分解产出，示例）
  Common  → 材料#60041   Base=1  每物品等级 +0.02  概率 100%
  Common  → 材料#60036   Base=1  每物品等级 +0.003 概率 <100%

GatherableConfigs
  Plant(0): 范围 0.6, Mode=Instant, 动画 "Pickup"
  Mine(1) : 范围 0.6, Mode=Cast,    duration 见 JSON
```

> **数值设计观察**：成功率数组前 4 级必成（1.0），第 5 级起 0.75→0.5→0.4→0.3→0.2→0.1 递减，第 11、12 级又回到 1.0。
>
> ✅ **「后两级 = 特殊强化」已定案（2026-10-10，指令级）**。强化服务（当期类名 `ip`，语义别名
> `Upgrade.Ingredients`@`0x7F6380`）反编译出的分支条件是「**目标等级 < 0xB（11）走稀有度配方，
> ≥ 11 走 `SpecialUpgradeRecipe`**」——正是成功率数组的最后两项（都为 1.0）。
> 材料数量随目标等级缩放：目标 ≤10 按 `目标等级²` 倍、≥11 按 `目标等级−9` 倍（→11 级 ×1、→12 级 ×2），
> 见 `amount = 倍率 × Ingredient.Amount`。上限由 `Upgrade.MaxUpgradeLevel`@`0x7F6080` 读
> `MaxEquipmentUpgradeLevel`（缺省回退 0xC=12）。另有支线：稀有度 ∈ {Rare, Legendary, Divine}
> 且目标等级 ∈ {9, 10} 时额外要求 `ExtraUpgradeMaterials[槽位]`（查不到该槽条目会直接抛异常）。
> 稀有度→配方选择器 `GameConfig.UpgradeRecipe`@`0x70F940` 是 `UpgradeRecipes` 的线性查找，**无等级入参**。
> 证据：REA 反编译（GameAssembly `d46f0a32…`），三条地址已入 `aliases.json`（`Upgrade.*`）。
> 字段名更正：GameConfig 字段是 **`SpecialUpgradeRecipe`**，旧稿按资产名误写为 `UpgradeRecipeSpecial`。

  EliteDamageMultiplier = 1.5

难度档位 DifficultyTiers
  ┌────────────┬────────┬───────┬──────────────┬───────────┬───────┬──────────────┬──────────────┐
  │ Difficulty │ HP 倍率 │DMG倍率│ Loot/地图等级 │Gold/地图等级│ EXP倍率│ 物品等级/地图 │Boss材料倍率  │
  ├────────────┼────────┼───────┼──────────────┼───────────┼───────┼──────────────┼──────────────┤
  │ Normal  0  │  1.0   │  1.0  │     0        │     0     │  1.0  │      0       │     1.0      │
  │ Nightmare1 │  3.5   │  1.35 │    0.005     │   0.005   │  1.5  │      1       │     1.5      │
  │ Inferno1 2 │  6.0   │  1.8  │    0.01      │   0.01    │  2.0  │      2       │     2.0      │

MinMythicDifficulty = 2（Inferno1）

> **数值设计观察**：难度提升是**非对称**的 —— 生命 ×6.0 但伤害仅 ×1.8，即"变耐久而非变更致命"，符合挂机游戏"降低暴毙挫败感、拉长战斗时长"的设计取向。
