# 装备对比扩展到 11 槽位 + 每个伤害技能秒伤对比

## Context（为什么做）

GUI「装备对比」页目前只能对比**武器**（当前武器 vs 候选武器），结果区只给两条 DPS 与乘区 A–D 条。
用户希望：

1. 把「当前武器 / 候选武器」区域扩展为**十一种装备**——武器、头盔、胸甲、裤子、靴子、腰带、
   戒指1、戒指2、项链、手套、护肩（**不含披风/Back**），戒指两只分别独立对比。
2. 结果区为**当前职业的每个伤害技能**（如战士的旋风斩/半月斩）新增一行「当前秒伤 / 候选秒伤 / 变化」。

已澄清的口径：技能用**秒伤(DPS)**；防具/饰品槽的结果指标**沿用 DPS 变化**（不新增生存指标）。

现状关键事实（已读代码 / 数据确认）：

* 内存快照 `equipment` 有 12 槽（slot 0..11），`EquipSlotType` 恰为 1..11；
  `memory_offsets.json.equip_slot_id_to_type` 给出 slot→type 映射。
  **注意 slot 9=护肩(type 10)、slot 10=手套(type 9)，顺序与直觉相反**，标签一律以下拉映射为准。

* 装备词条实测**恒为 Flat(type 0)**（`equipment_editor._ALLOWED_TYPES=[0]`），这是本方案可逆减法的前提。

* `CharacterProfile.to_sheet` 装配 base(残差，含已装备防具/饰品词条) + assembled(仅孔位宝石) + paragon；
  **当前武器不在 base**（compare 时另行叠加）。`from_snapshot` 只把武器与宝石从 nsq 面板扣出。

* 技能倍率已逆向：`docs/04 §6.2`，`DamageEffect.AttackScaling`（Base+PerLevel），
  `gamedata.ability_attack_scaling(name, level)` 已实现；每个 DamageEffect 有独立 `DamageType`。

* 技能 `Cooldown` 多数为默认 0（Obscured 默认 hash=723851361、值≈denormal），不可靠；少数有真值。

* `HeroData.Class @ 0x30`（Barbarian=1/Hunter=4/Sorcerer=2/Monk=8）；`so_dump/HeroData.json` 的
  `Abilities` 用 pathID 引用 `AbilityData`，可据此得到「当前职业的伤害技能」清单。

## 目标

* 「装备对比」页支持选择 11 个槽位，当前/候选两侧可编辑该槽装备，比较其 DPS 影响。

* 结果区新增技能秒伤对比表（职业伤害技能逐行）。

## 改动设计（分文件）

### 1. 计算内核 `tools/deskrawl_calc/engine.py`（最小、默认等价）

* `DamageModel.__init__` 增参 `skill_scaling: float = 1.0`。

* `attack_damage()` 改为：

  ```python
  core = self.weapon_damage + self.skill_scaling * self.sheet.final(StatType.WeaponDamage)
  return (core + self.skill_scaling * self.sheet.final(StatType.Damage)) * self.primary_stat_multiplier()
  ```

  `skill_scaling=1.0` 时与原式**逐位等价**（保留原结合顺序，勿改写成 `weapon_damage+(F20+F3)`）。
  依据 `docs/04`：`attackDamage = (BaseDamage + scaling×(Final(20)+Final(3)))×(1+Final(主属性)/100)`。

* `compare_weapons` 经 `**attacker_kw` 透传，无需改。

### 2. 数据层 `tools/deskrawl_calc/gamedata.py`

* `heroes()`：加载 `HeroData.json`，按 `_name` 索引。

* `hero_class_info(hero_class)`：返回该职业的 HeroData 记录（按 `Class` 匹配）。

* `abilities_for_class(hero_class) -> List[str]`：`Abilities` 的 pathID → `AbilityData._name`。

* `damage_skills(hero_class, level) -> List[dict]`：过滤含 `DamageEffect` 的技能，每项含
  `{name, ability_name, level_req, mana_cost, tags, can_crit, damage_type, scaling,
    cooldown, channel_duration, tick_rate}`；`damage_type/scaling` 为该技能各 DamageEffect
  的逐项列表（多段技能分别计入）。沿用现有 `ability_damage_effects` / `unwrap` / `leveled_value`。

### 3. 档案模型 `tools/deskrawl_gui/core/profile.py`（+ 新文件）

* 新建 `core/item_draft.py`：`ItemDraft`（`name/affixes/upgrade_level/gems/equip_slot_type/
  item_level/rarity/source`），`to_mods()`、`to_dict/from_dict`，复用 `apply_upgrade`。
  仅用于**非武器槽**；武器槽继续用现有 `WeaponDraft`（保持 `weapon_current/weapon_candidate` 语义与
  selftest 锚点不变）。

* `CharacterProfile` 增字段（均带默认值，旧构建 JSON 兼容）：

  * `hero_class: Optional[int] = None`

  * `compare_slot: int = 0`

  * `slot_current: Dict[int, ItemDraft]`（键 1..10）

  * `slot_candidate: Dict[int, ItemDraft]`（键 1..10）

  * `bag_items: List[dict]`（泛化自 `bag_weapons`，含全部装备类型）

* `to_dict/from_dict` 同步读写。

* `from_snapshot`：

  * 读 `hero_class`（见 §5），写 `slots`（slot 1..10 建 `slot_current`，词条经 `apply_upgrade`
    折算——base 残差里是**已强化**的 nsq 值，不折算会留残差）；slot 0 维持现状。

  * `bag_items`：收 `1 <= equip_slot_type <= 11` 且**有实例 modifiers** 的条目（无实例数据只汇总一条
    告警，避免 100+ 刷屏）。武器侧行为与旧 `bag_weapons` 等价。

* `AssemblyItem` 增 `slot: int = -1`（宝石归属槽）；`from_snapshot` 填该槽，供 §4 精确减去孔位宝石。

### 4. 计算服务 `tools/deskrawl_gui/core/calc_service.py`

* `compare(profile, gd, slot=None)`（默认 `profile.compare_slot`）：

  * `slot == 0`：走现有 `compare_weapons` 路径（不变）。

  * `slot 1..10`：`base = to_sheet(gd).clone()`；按 `AssemblyItem.slot==slot` **减去**该槽当前件的词条与
    孔位宝石（`add_mod(Modifier(s,t,-v))`，全 Flat 可逆；若遇 type≠0 → 告警并跳过），再加当前件/
    候选件各自的 mods + 孔位宝石（宝石按 `equip_slot_type→category` 取 `gd.gem_modifiers`）。
    于是 **当前侧 ≡ 基线 to\_sheet**，仅候选产生 Δ。`weapon_damage/base_speed/skill_multiplier`
    仍取 `weapon_current`（武器决定攻速）。

  * `CompareResult` 增 `slot: int`、`slot_label: str`；`current_sheet/candidate_sheet` 供技能复用。

* 新建 `core/skill_service.py`：`skill_rows(profile, gd, cur_sheet, cand_sheet) -> List[SkillRow]`。

  * 技能集 = `gd.damage_skills(hero_class, profile.skill_level)`（hero\_class 为空则返回空表）。

  * 每技能：按 `DamageType` 分组建 `DamageModel(sheet, dtype, weapon_damage=base_damage,
    skill_scaling=scaling, primary_stat=...)`；单次期望 = `model.attack_damage() *
    model.compute(target).expected_mult`；多段求和得「每次施放伤害」。

  * 秒伤 = 每次施放伤害 ÷ `interval`，`interval = cd_eff` 若 `>0.05` 否则 `1/effective_attack_speed`；
    `cd_eff = cd_wo(level) × (1 - min(0.85, Final(CooldownReduction)))`（`sheet.capped` 已封顶）。

  * `SkillRow = {name, ability_name, level_req, current_dps, candidate_dps, delta, delta_pct,
    interval_note}`；逐技能对当前/候选两张 sheet 各算一次。

> 🔶→✅ 标注（2026-10-10 已核，见《文档置信度待核清单》③-13）：技能秒伤仍为**估算**，但误差已按
> `AbilityData` 全量 124 条量化收窄——前摇/收招玩家技能恒 0（已计入，实测不改数值）、多段按多个
> `DamageEffect` 逐段求和、引导技能按「前摇+持续+收招+冷却×(1−CDR)」整段周期计（**修正点**：旧口径
> 忽略引导冷却，7 个引导技能里 6 个有 2.5~18s 冷却）；未计法力为口径选择。
> `StandingTime`/`IsStandingUponCasting` 是施法期位移锁，不在伤害链上。
> 绝对值为估算，但**当前↔候选的 Δ% 在两侧同模型下可靠**。

### 5. 内存导入 `tools/deskrawl_gui/core/memory_import.py` + `memory_offsets.json`

* `memory_offsets.json`：`hero_data` 增 `"class": "0x30"`。

* `_read_slots`：把「仅 type==1 附实例」放宽为 `1 <= equip_slot_type <= 11`。

* 新增 `_read_hero_class()`：`GameManager+0x38 → HeroData+0x30`，类名自校验，值 ∈ {1,2,4,8}
  否则告警并返回 None；放入 `payload['player']['hero_class']`；`import_snapshot` 透传；`validate`
  增加值域校验。

* `from_snapshot` 从 payload 取 `hero_class`（同时兼容 `meta.hero.class` 夹具注入）。

### 6. 视图 `tools/deskrawl_gui/widgets/`

* `equipment_editor.py`：顶部增**槽位下拉**（11 项，键 = 内存 slot 0..10，标签取自
  `equip_slot_names`）；按槽绑定编辑器到 `weapon_*`（slot 0）或 `slot_current/slot_candidate[slot]`；
  非武器槽隐藏 基础伤害/攻速/技能倍率 行与武器元信息；bag 下拉按该槽期望 `equip_slot_type`
  （`equip_slot_id_to_type`；戒指两槽同为 7）过滤 `bag_items`。切换槽写 `compare_slot` 后 `refresh()`。
  为控行数，把单件编辑器抽成 `widgets/item_editor.py`（`ItemEditor`），`equipment_editor.py` 只做装配。

* `compare_view.py`：表头文案随槽名（如「当前头盔 DPS」）；在乘区条下新增**技能秒伤对比表**
  （列：技能 / 当前秒伤 / 候选秒伤 / 变化 / Δ%），并在表上方放 职业下拉（`hero_class` 回填，
  手工构建可选）+ 技能等级 Spin（默认 `profile.skill_level`）。数值列用户可排序用 QTableWidget 即可。

* `app.py`：刷新链不变；`reload` 时让 `equipment_editor` 重建槽/ bag 下拉。

## 回归与自检（`tools/deskrawl_gui/selftest.py` + fixtures）

* **首要验收**：`ANCHORS`、`_demo_direct`、`_engine_ok`、`_equipment_checks`、`_rank_checks`、
  `_build_roundtrip` 必须**不变**（默认 `slot=0`、`skill_scaling=1.0` 应逐位等价）。若锚点漂移即证明
  `attack_damage` 乘序写错。

* `_snapshot_checks`：`bag_weapons` → `bag_items` 引用与 `bag_combo` 索引同步更新（断言语义保持）。

* 新增断言：

  * 逐槽对拍：对 β 夹具切到某防具槽，`current_dps == baseline`（基线即 `slot=0` 之外的当前构建），
    且候选改词条 → Δ 方向正确、反向验证（改符号必变红）。

  * 技能表：给夹具 `meta.hero` 注入 `{"class": 1}`（Barbarian），断言技能表非空、行数=该职业伤害技能数、
    当前↔候选 DPS 与引擎直算（独立构造 DamageModel + skill\_scaling）对拍 <0.5%。

* **须给** **`fixtures/snapshot_beta.json`** **的** **`meta.hero`** **增加** **`"class": 1`**，否则技能新功能在夹具下无回归网。

* 行数（棘轮 ≤800）：`equipment_editor`(\~332)、`calc_service`(\~321)、`profile`(\~416) 均有余量；
  新增逻辑分散到 `item_draft.py` / `skill_service.py` / `item_editor.py`，避免单文件触线。

## 假设与限制（写入代码注释 / 沿用仓库标注）

* 技能秒伤的区间模型为估算（🔶→✅ 已核收窄，见 §「🔶→✅ 标注」）；逐技能等级用统一 Spin——
  **实测定案（2026-10-10）**：`Player+0x230` 运行时为空 `Dictionary`（count=0，键类型无法自证）、
  存档槽 `LearnedAbilities=[]`，**没有可导入的逐技能等级数据源**，故维持单一等级口径
  （探针：`tools/scripts/probe_skill_levels.py`；旧字段名 `nst` 补丁后已改名）。

* 不新增防御侧指标（按用户选择沿用 DPS）。

* 披风/Back（slot 11）按用户要求不纳入。
