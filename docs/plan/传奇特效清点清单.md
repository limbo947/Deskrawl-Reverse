## 1. 判定口径

| 判定 | 含义 | 能否进「当前↔候选」静态 DPS |
|---|---|---|
| **A** | 数据齐备、可复用现有池/乘区直接建模 | ✅ 能（对比 Δ 直接受益） |
| **B** | 数据齐备，但需新增乘区，或改命中模型/`_rates` | ✅ 能（需扩模型） |
| **C** | 数值型，但取值依赖**运行时状态**（叠层/召唤数/法力比/计数） | ⚠️ 需实机/存档喂值或稳态近似 |
| **D** | 触发/行为类（条件触发的行为），不落在静态 DPS 口径 | ❌ 不建模（写明理由） |

> `D` 类并非「无法折算」：部分带 `Chance` + `List<AbilityEffect>` 的（如 `TriggerEffectsOnHit`）
> 理论上可折「触发率 × 期望伤」，但会把工具从「面板口径」推向「实战模拟」，**当前口径不做**。

## 3. 建议排期

1. **首批（A，32 条）**：可复用现有池——`ConditionalDamage`/`ConditionalCritDamage`/`ConditionalCritChance`
   → 条件池与暴击乘区；`AbilityTagCritDamage` → 按技能行过滤；`AbilityModifier`/`AbilityChannelModifier`
   → `ability_mods` 通路；`StatConversion` → `StatSheet` 换算。**对 DPS 数值影响最直接。**
   **进度（2026-10-17）**：**首批 A 全部完成**——组1/组2/组3/组4（含 `StatConversion`），见 §5。
2. **次批（B，22 条）**：需扩模型——`AbilityEffectOverride`（技能段替换）与投射物/召唤形态类
   （`ProjectileCount/Size/Lifetime/Deflect/SpawnCount/StrikeSplash`）要先立「命中数/命中模型」口径；
   `DivineHelmet3` 只差目标精英开关。
3. **C（22 条）**：数值型但依赖运行时——已有 `StatusEffectController.lyk` 的读取链（叠层 `lxn`），
   `StatPerStatusStack`/`DamagePerStatusStack` 可直接接；召唤数/法力比需另取。
4. **D（35 条）**：**不建模**——触发/行为类不落在「面板 ↔ 候选 Δ」口径；若将来要，需先立「实战模拟」口径。
