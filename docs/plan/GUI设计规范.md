# GUI 设计规范：Binance 风格重构

> **依据**：根目录 [DESIGN.md](../../DESIGN.md)（Binance 设计语言分析）。
> **范围**：`tools/deskrawl_gui` 的界面结构、视觉令牌与交互流程；计算内核 `deskrawl_calc` 不改。
> **状态**：已落地（2026-10-20）。`--selftest` 87/87、`--smoke` 退出码 0。

---

## 1. 设计目标

把「数值计算台」从一张参数表单重排为一个**数据产品界面**：

1. **先结论后细节**：每页首屏先给用户要的那个数（属性最终值 / 换装 Δ% / 候选排序），参数与控制下沉到侧栏或次要区。
2. **单一强调色**：只保留 Binance 黄 `#FCD535` 承担主 CTA 与关键数值；其余靠画布/卡片/细边线三级色块分层。
3. **涨跌即语义**：Δ 用涨绿 / 跌红，且不做成卡片底色；同一语义在数字、结论条与表格里保持一致。
4. **数字可扫读**：所有价格/伤害/百分比走等宽字体栈（Consolas → 雅黑回落），对应文档里的 BinancePlex。
5. **保留全部既有功能**：导入链、只读约束、撤销/重做、会话恢复、构建库、整套对比、DPS 实测框、帮助检索都不因改版丢失。

## 2. 设计令牌

### 2.1 色板（`tools/deskrawl_gui/core/theme.py` + `resources/style.qss`）

| 角色 | 深色（默认） | 浅色 | 用途 |
|---|---|---|---|
| 画布 canvas | `#0B0E11` | `#FFFFFF` | 窗口 / 顶栏 / 页面底 |
| 卡片 surface | `#1E2329` | `#FAFAFA` | 卡片、输入框、菜单 |
| 抬升面 raised | `#2B3139` | `#EAECEF` | 悬停、选中、全部细边线 |
| 次级面 sunken | `#1A1F25` | `#F5F5F5` | 斑马纹、已装配清单、实测框 |
| 禁用底 disabled | `#14181D` | `#F5F5F5` | 禁用控件 |
| 主黄 primary | `#FCD535` | `#FCD535` | 主 CTA / 关键数值 / 勾选·单选选中态（跨主题不变） |
| 主黄按压 | `#F0B90B` | `#F0B90B` | CTA hover / active |
| 主黄禁用 | `#3A3A1F` | `#EFE6C7` | 禁用 CTA |
| 黄底文字 | `#181A20` | `#181A20` | 黄底上的黑字（唯一组合） |
| 正文 body | `#EAECEF` | `#181A20` | 运行正文 |
| 标题 title | `#FFFFFF` | `#181A20` | 高对比标题 / 选中项 |
| 次要 muted | `#707A8A` | `#707A8A` | **仅禁用态**文字（对比度不足，不做可读正文） |
| 次级弱化 faint | `#929AA5` | `#5E6673` | 表头、说明、导航未选中、次级标签（可读次级文字统一用它） |
| 黄系文字 / 数值 | `#FFD84D` | `#8A6200` | ⓘ、可点文字、传奇词条、DPS 数值（主黄在白底对比度不足） |
| 选中底 selection | `#2B3139` | `#EAECEF` | 输入框 / 正文的选中文字底（**不用**主黄） |
| 图标 icon | `#7E8896` | `#7E8896` | 图标与箭头描边：SVG 不参与 QSS 换色，故自身须两种画布上都 ≥3:1 |
| 涨 up | `#0ECB81` | `#0ECB81` | Δ 上涨（跨主题不变） |
| 跌 down | `#F6465D` | `#F6465D` | Δ 下跌 / 错误 |
| 聚焦 focus | `#3B82F6` | `#3B82F6` | 输入聚焦细环 |

规则：**QSS 只写深色令牌值**；浅色由 `LIGHT_MAP` 单次替换。品牌色（黄/涨绿/跌红/聚焦蓝/图标灰）
采用恒等映射，其余令牌必须翻转。新增色值必须登记进 `LIGHT_MAP`，否则 `--selftest ui` 的
「主题令牌」断言会先红（浅色下会留一块暗底）。

**图标不参与换色**（重要）：`load_qss` 的色值替换只作用于 QSS 文本，`resources/icons/*.svg`
与 `arrow_*.svg` 是独立资源。所以它们的描边不能用任何主题专属令牌——原值 `#929AA5` 在
白底上只有 2.75:1（低于 WCAG 1.4.11 的 3:1），浅色主题下图标会淡到看不见。现统一为中性灰
`#7E8896`：白底 3.6:1 / 画布 5.4:1 / 卡片面 4.4:1，两套主题共用一份图标。

对比度规则：`#707A8A` 在卡片面 `#1E2329` 上只有 3.65:1（白底 4.34:1），低于 WCAG AA 的
4.5:1，因此**只用于禁用态**；一切可读的次级文字（表头、卡片说明、ticker、诊断行）走
`#929AA5`（卡片面 5.7:1 / 画布 6.8:1），浅色下映射成 `#5E6673`（白底 5.8:1）。

### 2.2 字体

| 角色 | 字体栈 | 用法 |
|---|---|---|
| 正文 / 标题 | `"Microsoft YaHei UI", "Segoe UI"` | 中文正文、按钮、导航 |
| 数字 | `"Consolas", "Microsoft YaHei UI", monospace` | DPS、Δ%、表格数值、实测读数 |

文档的 BinanceNova / BinancePlex 为 Binance 授权字体，本工具用系统栈替代：
Nova → Segoe UI / 雅黑；Plex → Consolas（等宽、逐字回落到雅黑，混排仍整齐）。

| 层级 | 字号 / 字重 | 位置 | 文档对应档 |
|---|---|---|---|
| 页面标题 | 32px / 600 | hero band | display-sm |
| 卡片 / 分组框标题 | 16px / 600 | `Card` / QGroupBox 标题 | title-sm |
| 正文 | 13px / 400 | 全局 | body-sm |
| 说明 / 表头 / 徽标 | 12px / 400–600 | hint、表头、ticker、只读徽标 | caption |
| 结论 Δ | 32px / 700 | 对比结果 | display-sm（等宽） |
| DPS 数值 | 24px / 600 | 对比结果三格 | title-lg（等宽） |
| 实测读数 | 20px / 700 | DPS 计 | title-md（等宽） |

全部落在文档层级表内（32/24/20/16/13/12）；2026-10-20 前曾用 28/15/11 三个表外值，
已分别归入 display-sm、title-sm、caption。正文选 13（body-sm）而非 14（body-md）是密度取舍：
侧栏 7 行表单 + 巅峰 15 行表 + 属性表 67 行共享一屏，14px 会把三者一起顶出首屏。

数字字形的落地方式：QLabel 类由 QSS 直接指定等宽栈；**表格按列**走 `MonoDelegate`
（`widgets/common.MonoDelegate`，只换字族、字号与颜色仍由 QSS 决定）。名称列必须留在
正文栈——给整表设等宽会把中文/内部名也变成等宽，等于违反「数字用 Plex、文字用 Nova」。

### 2.3 形状与间距

- 圆角：按钮 6px、输入框与表格 8px；卡片 12px；状态徽标胶囊 11px。不使用大圆角与阴影。
  微控件取最近的令牌档：进度条与勾选框指示器 4（sm）、滚动条手柄 5（8–10px 宽上的等效
  pill）、单选钮与滑块手柄 8（50% 圆，`rounded.full` 允许）——不再使用 3/5/7 这类表外值。
- 间距：4 / 8 / 12 / 16 / 24 / 32。页面外距 24px（左右一致）；页面内卡片垂直间距 8px（三页统一，
  `role_page` / `compare_page` / `assembly_center` 同值）；QSS 的 padding 一律取 4 的倍数。
- 卡片内距**分两档**：常规卡 `Card` 及装配工具栏 16/14；嵌入 / 紧凑卡 12（`ItemEditor`、
  `SlotOverview`、实测框——它们在 QGroupBox 的 4px padding 之上再加 8）。8/4 类分栏里这几张
  卡要共享一屏高度，统一成 14–16 会把词条表与巅峰表挤出首屏（见 §6 偏差 13）。
- 层级：**无阴影、无渐变**。深度只来自 `canvas → surface → raised` 的色阶与 1px 细边线。
  细边线一律用 `raised`（`#2B3139`）：换到 `surface` 色在浅色主题下会淡成 `#FAFAFA` 而消失。
- 焦点：输入类与按钮在键盘聚焦时置 1px `#3B82F6` 描边；无边框的平铺按钮（导航链接 /
  标签条 / 文字按钮）改为底色抬升一档。文档的「2px 50% 蓝环」在 QSS 里没有 `box-shadow`
  可用，1px 实心环是等效表达（见 §6 偏差 9）。
- **表格焦点要单列规则**：`QTableView[flat="true"]` 的去框规则与 `QAbstractItemView:focus`
  特异性相同（0,1,1），后者在前会被覆盖，而 `QTableView{outline:none}` 已关掉系统焦点框——
  必须再写一条 `QTableView[flat="true"]:focus` 放在去框规则之后，否则技能表与词条表在 Tab
  走查时完全看不出焦点。`--smoke` 的「焦点与可访问名」断言会检查这一条还在。

## 3. 界面结构

### 3.1 应用外壳

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 文件  编辑  视图  数据导入  帮助                          ← 24px 命令条（原生菜单）│
├──────────────────────────────────────────────────────────────────────────────┤
│ 构建  示例构建·猎人 · Lv70 · 未设职业    数据源  手工构建      只读·不写入游戏进程  │
├──────────┬───────────────────────────────────────────────────────────────────┤
│ ⌂ 角色    │  页面 hero band：标题 32/600 + 副标题 + ⓘ   [页面级动作 / 口径摘要] │
│ ⇄ 装备对比 │ ──────────────────────────────────────────────────────────────────│
│ ▦ 装配中心 │   主区 7                                     侧栏 3               │
│           │   ┌──────────────────────────────┐   ┌──────────────────────┐     │
│  （弹性）  │   │ 卡片（surface / 12px / hairline）│   │ 卡片                 │     │
│ [只读]    │   └──────────────────────────────┘   └──────────────────────┘     │
│ [浅色主题] │                                                                    │
│ [从游戏导入]│                                                                    │
└──────────┴─────────────────────────────────────────────────────────────────────┘
```

- **命令条**：保留原生菜单（文件/编辑/视图/数据导入/帮助）。桌面工具的可发现性与快捷键
  依赖它；样式压到 24px、弱化文字，不与页面内容争夺注意力。
- **左侧边栏**（`widgets/navigation.py: TopNav`）：176px（窗宽 <1180 自动收起为 64px 图标态，
  也可 Ctrl+B 手动切换）。上部 3 个页面链接（图标 + 文案，选中态 3px 黄左边线）；**操作簇钉在
  底部**：「只读」胶囊、主题开关、「从游戏导入」主 CTA。收起时操作簇与上下文条整条隐藏，
  动作走菜单等效入口（数据导入 / 视图 → 主题）。
- **上下文条**：34px 横向顶栏，常驻显示当前构建（名称 / 等级 / 职业 / 基线 DPS）与数据源
  （手工 / 内存导入 α·β + 快照时间），右侧一句只读承诺。切页不丢「现在算的是哪套数」。
  基线 DPS 在首次显示与换数据源时各算一次并缓存（整表重算约 1ms，编辑时每次按键都跑不值得），
  编辑之后它仍在——否则「常驻」只在刚导入时成立。
- **页面 hero**：标题 32px，副标题一句动线（与标题**同行**、底对齐落在基线附近）、
  ⓘ 承载长口径；右侧可放页面级动作
  （对比页的只读职业、装配中心的目标摘要 + 跳转）。
- **卡片**：`Card`（`widgets/common.py`）与 `QGroupBox` 共用一套观感；卡片内不再套表格外框。

要点：
- 宽表在主区：属性表 6 列、「只看常用」时收起三层分解列；11 槽总览固定在主区下方，**11 行全部可见**，不再被侧栏滚动截断。

- 交互不变：控件写回 `CharacterProfile` → `changed` → 主窗口轻量刷新；双击总览行跳到对比页对应槽。

### 3.3 装备对比页（8/4，窄窗自动重排）

```
hero：装备对比 / 选一个槽 → 填候选 → 看 Δ%      [技能按「野蛮人」列出]
[武器 头盔 胸甲 … 手套 披风(禁用)]                          [整套对比…（1 槽）]
[从背包/仓库载入 ▾]                                         [以当前件为起点]
┌──────────────────────────── 主区 8 ────────────────────────────┐ ┌──── 侧栏 4 ────┐
│ 对比结果                                                       │ │ 目标基础        │
│ 当前武器 DPS    候选武器 DPS     变化                           │ │ 预设/等级/血线  │
│ 198.218         226.606        ▲ +14.32%           [复制]│ │ 护甲/魔抗/减伤  │
│                                （+28.389 DPS，12px 附注）      │ │                │
│ ▬▬▬ 当前条   ▬▬▬ 候选条（涨绿/跌红）                            │ ├────────────────┤
│ 各词条贡献（单独移除后）：…                                     │ │ 技能（参考倍率）│
│ 技能 | 当前 | 候选 | Δ%                                         │ ├────────────────┤
├────────────────────────────────────────────────────────────────┤ │ 游戏实测        │
│ 当前武器（卡片）            候选武器（卡片）                     │ │ 换装预测 / 读数 │
│ 名称 / 基础伤害 / 攻速 / 技能倍率（或传奇词条）                  │ └────────────────┘
│ 强化/宝石 事实 或「与当前装备相同」                              │
│ 词条表：属性 | 类型(加法) | 数值(%) | ×                          │
│ [添加词条]                                                      │
└────────────────────────────────────────────────────────────────┘
```

要点：
- **结论区是唯一主视觉**：三格数值卡（当前 / 候选 / 变化），Δ 32px 涨绿跌红，DPS 数值走「黄系数值」令牌（深色主黄、浅色深金）；旁边「复制结论」把结论行 + 归因 + 技能表 + 口径注脚一起进剪贴板。
- **Δ 分两级**：32px 只放「▲ +14.32%」，绝对 ΔDPS 降为 12px 附注（`delta_abs`）。合成一行时
  （`▲ +14.32%（+28.389 DPS）`）单行最小宽度约 400px，会把整页最小宽顶到 **1276**——而 8/4
  分栏下主区只有约 980，结论区只能横向滚动、数字右侧被裁（实测修复前 1440×900 即如此）。
  复制结论时两级会合回一行，脱离界面也读得出层级。
- **图形第二通道**：两根细条表示当前/候选的相对长度；候选条按涨跌着色。无候选时整块隐藏，避免 0 DPS 被读成暴跌。
- **槽位用标签条**（11 槽 + 禁用的「披风」）：一次点击直达，取代两点式下拉；`SegmentedTabs` 保留下拉语义子集（`findData/currentIndex/setCurrentIndex`），业务与自检无感。
- **当前件只读、候选可编辑**：导入态当前件固定为游戏事实；候选可「从背包/仓库载入」或「以当前件为起点」。
- **右栏**：目标基础（护甲/魔抗、减伤/伤害类型并成两行省高度）、参考技能、实测框（钉在底部，不随目标滚动）。
- **实测框与结论同语义**：换装预测的涨跌色也按三态判（|Δ| < 0.05% 不给涨跌色，回落黄系基色）——
  换上与当前完全相同的候选时必须读成「没变」，不能读成一次上涨。
- **窄窗（< 1320px）**：页面左右栏改为上下堆叠；结论卡自动移到编辑器**上方**（`EquipmentEditor.set_result_first`），保证 1280×720 首屏先看到 Δ，编辑器向下滚动。

## 4. 交互流程

### 4.1 数据导入（只读）

```
右上「从游戏导入」/ 菜单「数据导入」
   → 版本指纹自检（不符：CTA 禁用 + 原因 tooltip + 浮层告警）
   → 1s 节流 + 后台 QThread 读内存（按钮进入「导入中…」）
   → preserved_import：只换角色数据，保留目标/参考技能/伤害类型/开关记忆
   → 面板口径复算（失败只降级并在浮层说明）
   → 撤销栈 reset → 三页 reload → 上下文条更新数据源与快照时间
```

硬约束不变：只 `OpenProcess(0x0410)` + `ReadProcessMemory`，不写入游戏进程、不修改安装目录。

### 4.2 换装对比

```
点槽位标签 → 播种/载入候选 → 改词条（百分比按 % 输入）
   → 词条 changed → compare 重算 → 三格结论 + 两根条 + 技能表即时更新
   → 停止编辑 250ms 后补算「各词条贡献」
   → [复制结论] / [整套对比…]（多槽合计 + 逐槽边际，明确不可相加）
```

### 4.3 找更强的

```
切类别标签 → 调参数（部位/等级）→ 120ms 合并后全量重排
   → 双击 / 回车 / 右键 / [加入构建] → 写入 assembled → 基线重算 → 属性表联动
```

## 5. 响应式行为

| 宽度 | 行为 |
|---|---|
| ≥ 1440 | 侧栏展开（176px）；7/3 并排（内容宽封顶 1440 居中）；对比页结论在编辑器下方，全部同屏 |
| 1180–1440 | 侧栏展开；7/3 并排 |
| 1100–1360 | 对比页左右改为上下堆叠，结论卡置顶；角色/装配仍并排 |
| < 1180 | **侧栏自动收起为 64px 图标态**（拉宽自动展开）；< 1100 三页都上下堆叠，侧栏滚动区接管溢出 |
| 最小 1024×680 | 保持可用：槽位标签条可容纳 11 项，表格横向不溢出 |

**分栏实配**（`setSizes` 初值）：三页统一 **960:412（7/3）**，不是文档字面的 8/4。为什么：
对比页编辑器（双编辑卡 + 结论区）最小宽约 860–890，8/4 需要 ≥1373 的窗宽才不出横向滚动
（70/30 在 1321 就够）；对角色 / 装配页，侧栏只有表单，给到 33% 只会在 1440 宽下留出 450px
的空表单区。对比页的并排/堆叠阈值相应取 **1360**（角色 / 装配仍为 1100）。登记于 §6 偏差 14。

**内容宽封顶 1440**（`common.cap_page_width`）：三页主体在超宽屏下不再跟随窗口拉满，
而是封顶 1440 居中——文档「产品面 1440」的落地。cap 只约束横向；纵向仍由滚动区 / 分栏分配。

**横向滚动为零（回归口径）**：1440×900 / 1280×720 / 1024×680 × 三页逐页扫描，页面内不得出现
可用的横向滚动条（`QAbstractScrollArea` 的 `horizontalScrollBar().maximum() > 0`）。修复前
1440×900 的对比页有两个：编辑区 284px（结论区 Δ 文本单行把最小宽顶到 1276）、右栏 77px
（两枚三位小数微调框各要 169px）。改法见 §3.3「Δ 分两级」与 `TargetEditor._field` 的最小宽度。
侧栏上线（占 176px）后，1024 窗宽靠**自动收起**（见上表）维持这一口径——编辑器最小宽 ~870，
只有侧栏收到 64px 才装得下。

**滚动兜底（硬约束）**：任何「固定高度的表 / 卡片」所在的主区都必须包在 `QScrollArea` 里
（`common.scroll_host`）。QSplitter 分不到高度时不会自己产生滚动条——实测 1024×680 下装配
中心候选表表体高度归零、角色页 11 槽总览少 5 行，界面看起来只是「空了」，没有任何报错。
宁可出现滚动条，也不许静默裁掉数据。

初始窗口默认 1440×900，但按可用屏幕区域的 94%/92% 收缩（`common.preferred_window_size`）——
1366×768 的笔记本上不会把结论区探出屏幕底边。

表格、卡片不做水平滚动；窄窗宁可竖排，也不压缩列宽（列宽被压到读不出数字时，表格就失去意义）。

## 6. 与 DESIGN.md 的对应与有意偏差

**直接采用**
- 深近黑画布 + 单一主黄 + 涨绿/跌红语义；卡片 12px 圆角、细边线、无阴影。
- 顶部导航 64px（页面链接 / 右侧操作簇；无品牌区）；主 CTA 黄底黑字。
- 数据表 = markets-table-card：卡片内 tab 行 + 表头弱化 + 行悬停；Δ 列彩色文字。
- 三格数值卡 = stat-callout-card；Δ 是最大字号；数字走等宽字体。
- 8/4 产品页分栏（主数据区 + 侧栏表单）。

**有意偏差（均已在实现里写明理由；12–19 为复审补登，并于同日第二轮修复中收敛到位）**
1. **没有营销 hero band / 浅色 footer**：这是桌面工具，纵向空间要留给数据；页面 hero 只保留标题-副标题-ⓘ，底部不再插一条浅色页脚。
2. **保留原生菜单条**：桌面工具的可发现性与快捷键依赖它；压成 24px 的弱化命令条，不参与品牌层级。
3. **导航改为左侧边栏**（2026-10-20，取代原「顶栏 top-nav-dark」方案；当日先精简掉品牌区，
   随后按用户要求整体移到左侧）：文档的 top-nav-dark 64px 横条不复存在——页面链接成左列、
   操作簇（只读 / 主题 / 导入 CTA）钉在侧栏底部，上下文条独占横向顶栏。选中态用 3px 黄左边线
   表达（横条的 2px 下划线在竖排上没有对应的「下方」）。窄窗自动收起见 §5。
4. **警告/错误色**：文档未定义告警色；本工具用主黄表示「需要注意」（如 α 降级、未命中名称），用跌红表示硬错误。涨绿不参与「成功」语义。
5. **字体替代**：BinanceNova/Plex 不可分发，改用 Segoe UI/雅黑 + Consolas，并保留同样的大小/字重层级。
6. **「披风不参与」保持禁用标签**：文档的 tab 行没有禁用态，但这里需要把「为什么列表里没有披风」显式化，避免玩家反复找。
7. **输入框高约 35px（文档 40px）**：侧栏要放下等级 / 三维 / 主属性等 7 行表单与巅峰 15 行表，
   40px 会把后者挤出首屏。主 CTA 仍按文档取 40px 高（触摸目标那一条不减）。
8. **表格行高 22–30px + 斑马纹替代行间细线**（文档 `markets-row` 是 12px 纵向 padding + hairline）：
   一屏要读 67 行属性 / 36 条候选，密度优先；分隔交给 `sunken` 斑马纹（§2.1 已登记该令牌）。
9. **焦点用 1px 实心描边而非 2px 50% 环**：QSS 没有 `box-shadow`/外发光，只能以边框等效；
   表格聚焦时内容内缩 1px 是同一原因的副作用。
10. **主 CTA 的横向 padding 取 24px、纵向靠 `min-height` 凑到 40px**：文档的
    `padding 12px 24px + height 40px` 若直译到 Qt 会得到 64px 高的按钮（QSS 的 height 含
    padding），取「总高 40」这一条语义。
11. **`#707A8A` 退为纯禁用色**：文档给它的用途（表头、说明）在卡片面上只有 3.65:1，
    低于 WCAG AA；可读次级文字改用文档同样提供的 `muted-strong`（`#929AA5`）。

**复审补登（2026-10-20 第二轮复核发现此前只在代码里、未写进本文的偏差）**

12. **正文取 body-sm（13px）而非 body-md（14px）**：页面标题（32/display-sm）、分组框标题
    （16/title-sm）、徽标（12/caption）均已归入文档层级表，只剩这一条是「默认正文选了哪一档」
    的取舍——侧栏 7 行表单 + 巅峰 15 行表 + 属性表 67 行共享一屏，14px 会把三者一起顶出首屏。
13. **卡片内距分两档 14–16 / 12**（见 §2.3）：文档的 24px 内距照搬会把巅峰 15 行表与词条表
    顶出首屏；嵌入 / 紧凑卡（词条编辑器、11 槽总览、实测框）统一取 12。
14. **分栏统一 7/3，不是 8/4**（见 §5「分栏实配」）：对比页编辑器最小宽约 860–890，
    8/4 需要 ≥1373 的窗宽才不出横向滚动；且三页侧栏都只有表单，33% 只会留出空表单区。
15. **内容宽封顶 1440 而非「无上限」**：已按文档「产品面 1440」落地（`common.cap_page_width`，
    三页接入）；与文档的差异只剩营销页的 1280 档未实现——本工具没有营销面。
16. **微控件圆角取等效令牌档**：进度条与勾选框指示器 4（sm）、滚动条手柄 5（窄宽度上的等效
    pill）、单选钮与滑块手柄 8（50% 圆）。不再使用 3/5/7 表外值。
17. **参数与搜索独立成工具栏卡**：类别标签条已移入候选表卡（markets-table-card 的
    「卡内 tab 行 + 表格」解剖）；工具栏卡只留镶嵌部位 / 等级与搜索——tab 换「看什么」、
    参数调「怎么排」，两张卡各说一件事。
18. **点击目标**：导航链接整条可点（高约 40px）、勾选框指示器已放大到 16×16；残余偏差是
    勾选框本体仍小于 28——但整行文字均可点，实际热区远大于指示器。
19. **主黄的使用边界**：勾选框选中态用主黄底（16px 指示器，不是大面积底色）；而**输入框与
    正文的选中文字底已从主黄收回 `raised`**——每个输入框选词都闪一片黄等于把强调色摊成背景。
