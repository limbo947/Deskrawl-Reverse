## 5. 核心数值结构体

### 5.1 `StatModifier`（属性修饰符，最小数值单元）✅

| 字段 | 类型 | 说明 |
|---|---|---|
| `Stat` | `StatType` | 目标属性 |
| `Type` | `ModifierType` | `Flat` / `PercentAdd` / `PercentMult` |
| `Value` | `ObscuredFloat` | 数值（通常以小数表示，如 `0.5` = 50%） |

### 5.2 `LeveledStatModifier`（随等级成长的修饰符）

| 字段 | 类型 | 说明 |
|---|---|---|
| `Stat` | `StatType` | 目标属性 |
| `Type` | `ModifierType` | 修饰类型 |
| `Value` | `LeveledFloat` | 等级曲线 |
| `Token` | `TokenSpec` | 提示文本格式 |

### 5.3 `LeveledFloat`（等级曲线，最常用的数值容器）✅

| 字段 | 类型 | 说明 |
|---|---|---|
| `Base` | `ObscuredFloat` | 1 级时的值 |
| `PerLevel` | `ObscuredFloat` | 每级增量 |

**取值函数**（`LeveledFloat.xf`，1.0.3 RVA `0x4AEEE0`；补丁前名 `xb`@`0x4A9370`）：

```
value(level) = Base + max(0, level − 1) × PerLevel
```

> 等级为 **1 基**；`level = 1` 时 `value = Base`。

### 5.4 `TokenSpec`（数值提示格式）

| 字段 | 类型 | 说明 |
|---|---|---|
| `Name` | `string` | 显示名 |
| `Format` | `string` | 格式串 |
| `Suffix` | `string` | 后缀（如 `%`） |
| `Highlight` | `bool` | 是否高亮 |

### 5.6 `Obscured*` 反作弊数值类型

游戏使用 ACTk（Anti-Cheat Toolkit）混淆数值，IL2CPP 布局：

| 类型 | IL2CPP 大小 | 说明 |
|---|---|---|
| `ObscuredInt` | 16 B | `hash` + `hiddenValue` + `currentCryptoKey` |
| `ObscuredFloat` | 20 B (0x14) | 联合体 `f`/`i`/`b4` |
| `ObscuredLong` | 32 B (0x20) | `hash` + `hiddenValue(long)` + `currentCryptoKey(long)` |

> **对数值设计的含义**：所有配置数值在存档/运行时以 `hiddenValue XOR currentCryptoKey` 存储，防止内存修改。`LeveledFloat` 两个字段均为 `ObscuredFloat`，故一个 `LeveledFloat` 占 0x28 字节。

### 5.7 `[SerializeReference]` 序列化布局 ✅

`AbilityData.Effects` / `StatusEffectData.Behaviors` 等多态字段（`AbilityEffect` / `StatusEffectBehavior` 系列）：

```
主数据流:   int32 count + count × 8B managed-ref 键        ← 仅"指针"
字段区之后:  [int32 A][int32 N]                            ← 托管引用段
             N × { [u64 typeHash][string 类型名][string 命名空间][string 汇编名][该类型字段…] }
```

- 类型名**明文存储** → 具体类型可精确判定；
- 已据此解出技能效果 **124/124**、状态行为 **88/95**（见 08 篇 §11）。

> 对比：`EquipmentEffect_*` / `TalentEffect_*` / `LifeSkillNodeEffect` 继承 **ScriptableObject**，
> 是**独立资产**（以 PPtr 引用），不属于 SR 载荷，按各自 schema 直接解码即可。
